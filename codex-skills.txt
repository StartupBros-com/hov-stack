# codex-skills.txt — which plugins/hov-stack/skills/ forks ALSO deploy to ~/.codex/skills.
#
# WHY AN ALLOWLIST AND NOT A BLANKET SYNC
#   plugins/hov-stack/skills/ holds Claude-specific skills (verify,
#   cass-rerank-local...) that reference Claude subagents, hooks or tooling. Syncing
#   the whole directory into Codex would ship broken or meaningless skills.
#
#   Second reason: a Codex deployment costs per-prompt budget there. Keep this list
#   short and justify additions.
#
# MODEL-INVOCATION GATING IN CODEX — READ BEFORE ADDING A SKILL
#   Codex never reads Claude's `disable-model-invocation` frontmatter. It has its own
#   gate in a SIBLING FILE, `agents/openai.yaml` inside the skill dir:
#
#       interface:
#         display_name: "Review Animations"
#         short_description: "Review motion code against a high craft bar"
#         default_prompt: "Use $review-animations to ..."
#       policy:
#         allow_implicit_invocation: false     # <- the gate
#
#   Verified 2026-08-06 against Codex CLI v0.145.0: the native musl binary carries the
#   validation string "`policy.allow_implicit_invocation` must be a boolean" and the
#   key set {"interface","policy","dependencies"}; OpenAI's own first-party skill ships
#   it at ~/.codex/skills/.system/review-agent/agents/openai.yaml. (`strings` on the
#   node_modules/.bin/codex wrapper finds nothing — it is a shim. Use the vendor path.)
#
#   THIS FILE PREVIOUSLY CLAIMED THE OPPOSITE — that no evidence existed Codex honours
#   any such gate, so anything listed here should be assumed ALWAYS-ON. The premise
#   (Codex ignores Claude's frontmatter key) was true; the conclusion was false, and it
#   left six deliberately-demoted forks silently auto-invocable in Codex until #219.
#
#   RULE: a fork listed below that is invoke-only in Claude MUST carry
#   plugins/hov-stack/skills/<name>/agents/openai.yaml with allow_implicit_invocation: false.
#   A fork that is model-invoked BY DESIGN (papercut) ships the interface block and no
#   policy block. skills-localize.sh warns on a listed fork with no gate file.
#
# HOW IT WORKS
#   skills-localize.sh apply  → rsync each listed plugins/hov-stack/skills/<name>/ into
#                               ~/.codex/skills/<name>/ (same copy semantics as the
#                               Claude tree; symlinked entries are never touched).
#                               The rsync is recursive, so agents/openai.yaml and any
#                               scripts/ dir travel with the fork.
#   skills-localize.sh check  → DRIFT: lines when a listed fork differs.
#   No-op when ~/.codex/skills does not exist (Codex not installed on this box).
#
# One skill name per line; must be a directory under plugins/hov-stack/skills/. `#` comments ok.
