# memory-dream v0.4.4

## Highlights

- The audit no longer stalls on an index line holding an unclosed link with many escaped brackets. Such a line could take minutes or more; it now takes milliseconds.
- Links in MEMORY.md are read exactly as before. The new pattern was checked against the old one on more than 15 million inputs.

## Details

Changes since v0.4.3. One code change, the link pattern in `audit.py`, with a
test in `tests/test_audit.py`. Found by GitHub code scanning (CodeQL alert 5).

`LINK_RE` read a link target as `(?:\\.|[^)])+`. A backslash matches both
branches, so an index line with an unclosed link and many `\(` pairs, such as
`- [x](a\(\(\(…`, made the pattern try every way of splitting them: 24 pairs
took 1.3 seconds and each extra pair doubled it. Memory index lines are written
by agents, so text copied from a page or a tool result could carry one.

The target is now matched with one branch per backslash case (an escape pair, a
backslash before a newline, or a lone trailing backslash). The same 24 pairs
take about 7 microseconds, and 20,000 pairs about 2 milliseconds. Before
landing, the old and new patterns were compared on every string of up to 9
characters over `]`, `(`, `)`, `\`, a letter and a newline, every string of up
to 7 characters with `<` and `>` added, and a million random longer strings:
the matched spans and targets agreed on all of them.

The harness's own `scripts/memory-audit.py` carries the same pattern and gets
the same change in this release.
