# memory-dream v0.4.3

## Highlights

- On a computer with more than one login, the dream pass now keeps note bodies in a scratch folder with a random name that only your login can open.
- If you point memory-dream at your own scratch folder, it now locks that folder to your login too. A folder someone else owns keeps its permissions.

## Details

Changes since v0.4.2. One code change, in `config.scratch_dir()`, with tests in
`tests/test_config.py`.

- **Fallback folder.** When neither `MEMORY_DREAM_SCRATCH` nor the session's job
  folder names a scratch folder, scratch was `/tmp/memory-dream-<pid>`, made with
  `exist_ok=True`. It followed the umask (usually `0755`, so other users could read the
  plan, shards and drafts), its name was predictable, and it reused a folder another
  user had made first. It is now `tempfile.mkdtemp(prefix="memory-dream-")`: `0700`, a
  random name, never an existing folder, made once per process. This is what
  `docs/EXTRACTION-DESIGN.md` already described.
- **Chosen folders.** A `MEMORY_DREAM_SCRATCH` folder, or the `tmp` folder inside the
  session's job folder, is set to `0700` when your login owns it. A folder someone else
  owns keeps its permissions, because chmod would fail there; point the override at a
  folder you own to keep it private.
- Sessions that have a job folder never reached the fallback. Sessions without one
  did, which is where the readable folder appeared.
- On Windows, permissions stay with the folder's ACLs, as before.
