# memory-dream v0.4.2

## Highlights

- Dream and eval passes now honour `MEMORY_DREAM_PASS_ROOT` and `MEMORY_DREAM_EVAL_HOME`; the prompts no longer hard-code paths under `~/.claude/logs/memory-dream`.
- The dream pass runs `build` before the two stages that read its results, and says plainly that its scratch folder holds note bodies.

## Details

Changes since v0.4.1. These are prompt and doc changes; the only code change is a
docstring.

- **Env overrides.** The shell lines in `commands/dream.md` and `commands/eval.md`
  hard-coded `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/logs/memory-dream/{eval,passes}`, so
  the prompts ignored the two overrides that `config.eval_home()` and
  `config.pass_root()` read. Stage 0, eval Stage 0, the Stage 4 `PS=` line and the
  recovery section now expand them. `eval.md` no longer says the JSON config file can
  set the eval home; `config.py` rejects that key.
- **Build order.** Stages 3.7 and 3.8 read `$PS/results/`, which exists only after
  Stage 4's `build`. Stage 3.7 now says to build once the 3.5 and 3.6 verdicts are in,
  and after any fix to refresh that cluster's `drafts_digest` and rebuild before 4.5.
  `build --findings` already enforced this order.
- **Scratch contents.** `commands/dream.md`, `docs/ARCHITECTURE.md` and the `config.py`
  docstring said scratch holds "plan/drafts/selection JSON, never memory bodies". The
  plan, the per-cluster shards and the drafts all carry note bodies; the text now says
  so, and the patch-set directory stays the only place results persist.
- **Fidelity verifier.** It runs as the Glob-only scribe, so the text no longer says it
  may cross-check other notes or run `git log` or `gh pr view`. Related notes go to it
  inline as an extra SOURCE, and repo-artifact claims go through Stage 3.6's lookups.
- **Drafter.** The action ladder includes `merge` as rung 3, between redescribe and
  compress, as the output contract already allowed.
