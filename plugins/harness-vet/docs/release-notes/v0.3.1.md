# harness-vet v0.3.1

## Highlights

- A vet now searches GitHub, the web and X for the best existing tools for the job, and runs the strongest contenders beside the candidate.
- harness-vet now ships from the hov-stack repository. Existing installs pick up the move on their next plugin update.
- X searches now use short groups of the words posts actually use, and each comparison run gets its own isolated browser profile.

## Details

This is the first harness-vet release from `plugins/harness-vet/` in
[StartupBros-com/hov-stack](https://github.com/StartupBros-com/hov-stack). The
marketplace entry switches from the old `StartupBros-com/harness-vet`
repository to this directory. That repository will be archived with a README
that points here.

The old repository's last release was v0.2.4. Version 0.3.0 was prepared there
but never released, so this release carries its changes:

- **Discovery.** Once the task is concrete, phase 1 searches three lanes
  (alternatives, implementation, experience) across GitHub, the web and X. One
  lane withholds the candidate's name. Each lane and source gets at most four
  queries, followed by bounded follow-up passes with a stated stop. Contenders
  are admitted on their own content only, share the three-deep vet slate, and
  run as phase-4 arms beside the bare model, the candidate and the incumbent.
  A slated contender that did not run is PARTIAL, and it blocks the
  candidate's own ADOPT or ADAPT until it runs.
- **Phase 4.** At least three runs per arm with their spread, a displacement
  control, calibration against a ceiling with normalized gain, and paired
  judging in both orders with flips counted as ties. Fixture items that cannot
  separate arms are dropped.
- **X queries.** An X query is two or three AND-groups, each an OR of the words
  posts use for that thing, and no group may require an output format or a
  library name. This replaces a wrong conclusion that the X lane was thin.
- **Isolation.** An arm, its regeneration step or a scorer that can launch a
  browser gets its own `XDG_CONFIG_HOME` and `XDG_CACHE_HOME` under the run
  root. A forked runner keeps its non-zero exit on a failed invocation.
- **Verify rules.** Planted-positive and precision-subset rules from two
  measured vets.

Three mentions of a private app and one path into the author's private
harness are now plain descriptions. One test was not carried over:
`tests/test_announce_pin.py` checked the old repository's announce workflow,
which hov-stack's release chain replaces.
