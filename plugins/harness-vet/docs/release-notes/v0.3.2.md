# harness-vet v0.3.2

## Highlights

- A vet now runs candidate code under `env -i`, so API keys and tokens exported in your shell no longer reach the code it tests.
- Model arms get only the variables that route them to the model, each passed by name.

## Details

Phase 4 used to say to run a candidate's tests "in an isolated sandbox (fresh
HOME, scratch env)". A fresh HOME hides dotfiles and config files, but not
variables the shell has already exported. On 2026-11-02 three vets ran
candidate code with the agent's environment inherited, and in one of them a
candidate's own test sent a real OpenAI key to api.openai.com.

- **Candidate code.** The Verify phase now gives one command line to paste
  into every verifier and arm prompt that runs candidate code: `env -i` with
  PATH, a scratch HOME and TMPDIR, and a scratch XDG pair. Any other variable
  is added by name, and never a credential. The evidence quotes the exact
  command line that ran, since that line is the record of isolation.
- **Model arms.** A `claude -p` arm also starts from `env -i`, with its own
  config directory, its XDG pair and only the model-route variables that are
  set. A candidate script the arm runs gets the candidate-code line inside the
  arm, because those variables can carry a model credential.
