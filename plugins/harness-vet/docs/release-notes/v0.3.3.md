# harness-vet v0.3.3

## Highlights

- A behavioral vet now writes down the rule that decides adoption before its runs, with a declared tolerance for cost and every other metric the candidate must not worsen.
- Cost comparisons log each run's prompt-cache tokens, so one run that starts on a cold cache no longer decides the result.

## Details

A re-vet of pstack on 2026-11-14 ran 131 headless Claude runs on one
synthetic fixture and hit three gaps in the phase-4 behavioral test. Each one
let the adoption rule fail for reasons that had nothing to do with the text
under test.

- **Countermetrics had no tolerance.** The skill treated a delta smaller than
  the run-to-run spread as noise only for the metric the candidate exists to
  improve. With no band on cost, a median 3.6% above the incumbent's counted
  as worse, although the incumbent's own costliest run sat up to 21% above
  its median. A tolerance is now declared, with how it was derived, before
  the runs. A band picked after the results are known is reported as post
  hoc.
- **The rule judged a unit that never ran.** The rule judged each candidate
  line on its own, but the final wording only ever ran as a pair, so no
  result could meet it. The rule now judges the unit that ran: each line
  alone in its final wording, or the pair as one unit.
- **Prompt-cache state swung cost.** A run that started on a cold prompt
  cache wrote about 10,000 to 13,500 more cache-creation tokens than a warm
  run of the same arm and task, enough to move a three-run median. Launching
  each run behind a warm one did not prevent it. Vets now log cache-creation
  and cache-read tokens per run, and before the batch declare the count that
  marks a run cold and a replacement rule keyed on that count alone, applied
  before any run's cost or outcome is read.

These rules come from one vet on one fixture. No vet has run under the new
text yet, and the replacement rule is a prescription this release has not
tested.
