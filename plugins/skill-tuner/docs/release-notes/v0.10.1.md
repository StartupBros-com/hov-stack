# skill-tuner v0.10.1

## Highlights

- skill-tuner now ships from the hov-stack repository. Existing installs pick up the move on their next plugin update.
- Doctrine v3.2 passes the gate as not worse than v3.1: 38 vs 34 confirmed findings over the same 15 documents.
- The skill now fires on briefs that ask to shorten a document, at routing parity with the old description.
- Endtask reports keep each run's resolved model, so the manifest's resolved model list is filled in again.

## Details

This is the first skill-tuner release from `plugins/skill-tuner/` in
[StartupBros-com/hov-stack](https://github.com/StartupBros-com/hov-stack).
The marketplace entry switches from the old `StartupBros-com/skill-tuner`
repository to this directory, and `/plugin install skill-tuner@hov` is
unchanged. The old repository's release train was frozen on 2026-10-24, and
the repository will be archived with a README that points here. Release tags
now look like `skill-tuner--v0.10.1`; the old `v0.10.0` tag stays readable.

Unlike the other migration releases, this one is not only a move: v0.10.0
(2026-09-23) left eleven pull requests unreleased. The numbers below refer to
the old repository.

- **Doctrine v3.2** (StartupBros-com/skill-tuner#72). Two body edits gated together against a fresh `claude-sonnet-5-5` baseline over the same 15 documents: 38 vs 34 confirmed findings, 95% CI [−0.56, +1.09], landed as *not worse* at δ = 1.0, never as better. A new `[craft]` bullet, "Rule, not incident" (write the behaviour a lesson asks for as one positive rule and leave the dated incident to the commit message), and the environment-as-source-of-truth sentences moved into their own bullet. Both keep `[craft]`; each has a falsifier in `FALSIFIERS.md`, and the isolated effect of either edit is unmeasured.
- **The description fires on shortening briefs** (StartupBros-com/skill-tuner#72). "shortening" joined the trigger list at routing parity (48/48 under both descriptions, ids hidden) after a live routing probe fired the skill 3/3 against the old description's 1/3 on a slimming brief. StartupBros-com/skill-tuner#74 measured one more word, "improving", with skill-creator installed as a live competitor, and refused it: with skill-creator present the skill fired on 0 of 3 improve briefs under either description, and without it the current description already fired 2 of 3 (`reports/trigger-improving-summary.md`).
- **Endtask reports keep the resolved model** (StartupBros-com/skill-tuner#65). The in-memory rows dropped `model_resolved`, so `manifest.resolved_models` was always empty. The field is retained, with regressions for deduplicated identities, unknown identities and budget-halted runs.
- **Announce workflow pin** (StartupBros-com/skill-tuner#66) rolled to 41bb6f8. hov-stack's own release workflows replace that per-repository copy, which did not come along.
- **Six de-duplication refactors** (StartupBros-com/skill-tuner#59 through StartupBros-com/skill-tuner#64): shared probe output instructions with byte-parity fixtures, an in-process CLI test helper, the routing skill test fixture, paired-case exclusion matching, the CLI passing-verdict policy, and portfolio source-error bookkeeping. Behaviour unchanged. The unit suite grew from 248 tests at v0.10.0 to 284 in the old repository; it runs 281 here, because `test_release_train.py`, which read that repository's release workflows, did not come along.
- **Harness-vet of nicobailon/skill-diet** (StartupBros-com/skill-tuner#71): verdict SKIP, three follow-ups (StartupBros-com/skill-tuner#68 and StartupBros-com/skill-tuner#69 landed with doctrine v3.2 above; StartupBros-com/skill-tuner#70 is open), and the vet's arm fixture under `experiments/skill-diet-arms-2026-10-29/`.

What changed in the move itself:

- Recorded eval data was scrubbed for publication without changing a number or verdict. Two private project names became `sample-project` and `sample-strategy`. Paths that named the author's old skills directory now name each skill's hov-stack location, the same way in every file, so `compare.py` still pairs the recorded reports.
- `tests/ci.sh` runs the old test workflow's checks: the unit suite, the doctrine-boundary grep, the stdlib-only check and the agentskills.io spec-divergence check.
