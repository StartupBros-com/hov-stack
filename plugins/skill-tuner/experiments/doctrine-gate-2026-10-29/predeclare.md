## Instruments and land rules

1. **Routing parity** (PLAYBOOK rule 4) for c69b: `tune.py routing-parity
   --config configs/swapgate8-routing-desc.json`, `neutral_ids: true`, 4
   trials, battery `configs/swapgate8-routing-battery.json` (5 should-fire
   cases including the vet's t1 brief, 5 near-misses that use the new
   trigger word on non-agent documents and code, 2 none-of-the-above), 5
   distractors. `writing-for-agents` is deliberately not a distractor: the
   battery measures the description's own routing power; the collision with
   a sibling doctrine skill is already recorded in #69.
2. **Live routing probe** for c69b: the vet's harness, skill installed, no
   slash token, t1 brief, 10 turns, 600 s cap, 3 reps per condition
   (`live-orig` = current description, `live-cand` = candidate description,
   same body). Count = runs whose `tools.txt` shows a `Skill` call naming
   skill-tuner.
3. **Land rule for c69b**: routing-parity verdict `land` AND live probe
   `live-cand` >= 2/3. Parity with no live gain is "no measured benefit",
   not a land. If c69b lands, its description is baked into every gated
   candidate before leg 0 runs, so gated bytes equal shipped bytes.
4. **Gate** (PLAYBOOK rule 7) for the body changes: leg 0 banks
   `swapgate8-probe-incumbent` (the untouched doctrine, or the doctrine with
   only the landed description). Leg 1 gates `combined` (c68 + c69a) against
   it with `--delta 1.0` findings per document, `alpha 0.05`, `sigma0 2.0`.
   Land rule: `tune.py gate` exit 0 (sequential verdict not_worse or better,
   corroborated by the fixed-n verdict of record). If leg 1 is refused, legs
   2 and 3 gate c68 and c69a alone with the same rule; each may land alone.
   If leg 1 passes, the isolated effect of each edit is not measured and the
   summary says so.
5. **Mechanism check** (not a land bar): the vet's fixture re-run with the
   landing candidate as the slash-invoked `/skill-tuner` arm: t1 (items D5,
   D7) and t2 (item D9), 3 reps each, graded by the vet's `grade.py`.
   Disclosure: the candidate text was drafted knowing the fixture's answer
   key, so a pass shows the rule fires on the fixture, not that it
   generalises. The gate stays the land bar.

## Fixed settings

- Model pin `claude-sonnet-5-5` on every instrument. This is a new
  comparability island: the swapgate3 to swapgate7 series pinned
  `claude-sonnet-5` under the pre-v0.8.2 envelope, `compare` refuses to pair
  across envelopes, and 13 of the 15 gate-set documents have changed since.
- Probe settings as the series: `max_findings 5`, `verify_trials 3`, the same
  15 local-skill documents (dotfiles `46f806da`, all 15 clean in the
  working tree at predeclaration), envelope `claude-p-user-message-isolated`.
- Pre-leg hard check: before every gate leg, re-hash the 15 targets and abort
  on any mismatch against the baseline manifest; fall back to `--exclude` for
  a drifted target only after recording the drift.
- Inputs are committed before each paid leg so manifests record a clean
  commit.
