I edited only `skills/shipit/SKILL.md`. The Releasing step now says to run `shipit check` right before every release, including staging and the prod release. It also says to confirm the check passed (exit 0 and no `no manifest` on stderr) and to stop if it didn't. Re-check is required whenever `shipit.yaml` changes. In Rules, I made the check mandatory with no exceptions for urgency, quick fixes or re-releases. I also added a rule to disclose and check immediately if a release went out unchecked. The History section now records last week's prod incident, and I reworded its old "The rule above comes from that incident" sentence, which now reads as if it refers only to the October one. While there, I fixed the example commands from `--env` to `--target`, because `shipit release --help` shows only `--target`, so the old examples would have failed.
