I edited `skills/shipit/SKILL.md`, the only file in the skill. The skill already said to run `shipit check` before releasing, so I made the rule harder to skip. Release step 1 now says to run the check immediately before every release, including each staging and prod step and any re-release. It also says the release must wait until the check passes, meaning exit 0 and no `no manifest` line on stderr. A failed check means fixing the manifest and re-running the check, and a check run earlier or before an edit to `shipit.yaml` doesn't count. The Rules entry now says the check can't be skipped even if the request is urgent, the change looks trivial, or the user hands over an exact `shipit release` command, and that a failed or `no manifest` check blocks the release. The History section now records last week's `shipit release --target prod` incident. I also fixed a bug in the same step: it used `--env staging` and `--env prod`, but `shipit release --help` shows the flag is `--target`, so I corrected both. I haven't tested the updated skill with an agent.
