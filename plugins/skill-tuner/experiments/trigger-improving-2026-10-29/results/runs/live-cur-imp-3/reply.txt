I rewrote `skills/shipit/SKILL.md` and checked it against the installed CLI. The main fix is that the old skill told agents to run `shipit release --env staging` and `--env prod`, but the CLI rejects `--env` (exit 2), so every release example now uses `--target`. I also made dry runs concrete by naming the `--dry-run` flag and requiring a dry run before any prod release. I removed the semver explainer and the claim that "Dry runs ignore `--retries`", which I couldn't verify against the CLI. The safety content is kept and moved up front: run `check` before every release, treat `no manifest` as a failure because `check` exits 0 anyway, and run `purge` only for a release the human names, with `--yes` only after they confirm. I tightened the notes-JSON section (I confirmed the CLI rejects both a bare array and an extra key) and merged the duplicated "dry run for prod" lines. The rollback steps are shorter, with the retry and reporting steps folded in, and I kept the March incident as a short background note.
