I rewrote `skills/shipit/SKILL.md` to be shorter and in the order an agent would act. The main correction is that the old release examples used `--env staging` and `--env prod`, but the CLI only accepts `--target`, so those are fixed. I confirmed three other claims by running the CLI. `shipit check` exits 0 and prints `no manifest` when the manifest is missing, bad `--notes-json` is rejected with exit 2, and `status` shows ACTIVE and PREVIOUS columns. I did not run `shipit release` without `--dry-run`, `shipit rollback` or `shipit purge`, so those commands are documented from the help output only. I removed the semver explainer, the Makefile history and the repeated rules, and I kept the March outage as a one-line reason for running `check`. I also added `--dry-run` as an explicit step for prod and marked notes as optional. All the safety guidance is still there: always run `check` first, treat `no manifest` as a failure, dry-run prod, and run `purge` only for a release the human names, with `--yes` only after they confirm. The rollback steps, retry advice and global options are kept.
