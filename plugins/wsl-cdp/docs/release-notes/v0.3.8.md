# wsl-cdp v0.3.8

## Highlights

- The mcp-add command now says when it could not create a temporary file, as with a missing or unwritable temp directory, instead of asking whether your .mcp.json is valid JSON.

## Details

- **`wsl-cdp mcp-add` reports a failed `mktemp` for what it is.** In 0.3.7 the command went on with an empty temporary path, the write failed, and it printed `wsl-cdp: FAILED to update <path> — is it valid JSON? (left unchanged)`. It now prints `wsl-cdp: could not create a temp file for mcp-add` and returns before it runs `jq`. `mktemp`'s own error line, printed just before it, gives the cause. Your `.mcp.json` is left unchanged in both versions.
- **Installer.** `install.sh` already stopped on a failed `mktemp -d` through `set -e`. The check is now written on the line itself, with no change in behaviour.
- **Tests.** The test scripts now check each fixture's `mktemp` call. A fixture that cannot be built stops that test file and fails the run; in 0.3.7 the test file went on against an empty path. The `mcp-add` check has no automated test. It was run by hand with a missing and with an unwritable temp directory.
