## Highlights

- Hand-started Oracle upgrades can now check attachment uploads without sending a message, then keep the current build if the candidate fails.
- The setup doctor now shows whether your Oracle version matches the last gated upgrade.

## Upgrade

Update pro-gate to install the new gate entry point. In hov-stack, run
`scripts/oracle-update.sh` to preview a bump, then `DRY_RUN=0 scripts/oracle-update.sh`
to start it. There is no timer. Existing installs gain no warning until a gated record exists.

## Details

The lane stages the candidate and holds every configured review slot through the no-Send
trial and promotion. A failed candidate is compared with the current build before rejection.
The static audit reads the candidate's whole `dist` and its manifest, and flags only click,
key and submit lines, dependencies, install scripts and `bin` entries that are new since the
live build; a reviewer accepts that exact set for that version by passing the digest the gate prints.
A rollback is recorded as a rollback, never as a gated bump.
Promoted dist bytes must match the staged digest; a mismatch restores the prior version.
The live trial remains unproven until the first hand-started bump is observed; issue #781
stays open for that run. Twenty trials cannot detect a small increase in upload failures.
