# pro-gate v0.65.10

## Highlights

- A busy host no longer stops a review because Oracle was slow to print its version. Each version read now gets 20 seconds instead of 5.
- When the Oracle build still cannot be read, the runtime says why on stderr: each try timed out, exited with an error, or printed no version.
- The fix is in the runtime. A host gets it when its runtime moves to 0.65.10, not when the plugin alone updates.

## Upgrade

Update the marketplace plugin and install the matching 0.65.10 runtime. The opt-in auto-updater follows the promoted plugin version. Existing review records and configuration need no migration. To change the new limit, set `PRO_GATE_ORACLE_VERSION_TIMEOUT` in the runtime's `.env`.

## Details

- **Why a slow start stopped reviews.** After a send that never reached ChatGPT, the next decision compares the Oracle build with the one recorded at that attempt. The runtime reads the build with `oracle --version`, at most twice. If neither read succeeds, the build is `unknown` and the decision is `stop-without-new-review` with reason `delivery-state-unavailable`, which `PRO_GATE_FORCE_ROUND` cannot override. Each read had 5 seconds. Under a 5% CPU quota, Oracle 0.20.0-sb.5 took about 7.4 seconds to print its version, so the read reported an installed, working build as unknown. A review on 2026-11-17 most likely stopped this way; that cause is inferred by elimination, because nothing recorded what the read returned (StartupBros-com/hov-stack#735).
- **The new limit.** Each read gets `PRO_GATE_ORACLE_VERSION_TIMEOUT` seconds, a whole number from 1 to 3600, default 20. Any other value, including 0, which `timeout` would read as no limit, uses the default. Two tries remain, so a read that hangs costs at most 40 seconds by default. The read runs only before a fresh review is sent and when a decision follows a recorded failed send.
- **The diagnostic.** When the build cannot be read, one stderr line starting `[pro-gate] Oracle build unknown:` names the command and how each try ended, or names a missing Oracle or `timeout` command. A successful read prints nothing.
- **What does not change.** An unknown build still stops the review the same way, and the decision contract, its corpus, the delivery facts and the doctor are unchanged.
