# pro-gate v0.65.9

## Highlights

- A review run or status check now stops if its temporary folder cannot be created, as when the temp directory is not writable, instead of carrying on with an empty path.
- The fix is in the runtime. A host gets it when its runtime moves to 0.65.9, not when the plugin alone updates.

## Upgrade

Update the marketplace plugin and install the matching 0.65.9 runtime. The opt-in auto-updater follows the promoted plugin version. Existing review records and configuration need no migration.

## Details

- **Review runs and status checks stop on a failed `mktemp`.** `oracle-review.sh` does not run with `set -e`, so in 0.65.8 a temporary folder that could not be created left its variable empty and the command carried on past that line, with its scratch files addressed at the top of the filesystem, for example `/findings.md`. Both commands now exit with status 1 right after `mktemp` reports the error.
- **What 0.65.8 did next, read from its code and not reproduced.** For an ordinary user, writes at the top of the filesystem are refused. A review run with the default output file then stopped at its output-file check with `cannot establish ownership of --out /findings.md`, a message that does not name the temporary folder. A status check kept going and could report no runs in flight, because the scratch files it builds its answer from were never written. Run as root, the scratch files would be written at the top of the filesystem.
- **The fix is in the runtime.** A host gets it when its runtime moves to 0.65.9, not when the plugin alone updates.
- **No change in behaviour elsewhere.** The installer, the runtime packager and the source validator already stopped on a failed `mktemp` through `set -e`. Three places already handled a missing temporary file and behave as before: result recovery, rejected-capture retention and reservation restore. Each of these now carries its check on the `mktemp` line itself, and so do the test scripts.
