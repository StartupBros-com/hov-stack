# pro-gate v0.65.7

## Highlights

- In a fork, `--pr N` now reviews the fork's own pull request N, not the upstream repository's.

## Upgrade

The marketplace plugin update brings the new skill, and the hourly auto-update timer or the
next `/pro-gate` run installs the 0.65.7 runtime. Nothing to change by hand.

## Details

- **A bare PR number in a fork.** When `--pr` was a number rather than a URL, the engine
  found the pull request's URL with `gh pr view N`, which picks gh's own default
  repository. In a fork checkout that default is the upstream parent, so the run reviewed
  the parent's PR N and recorded the result under the fork's name. That is wrong evidence for
  the PR being gated. The lookup now names the checkout's origin repository explicitly, the
  same repository the rest of the run already assumed. A full PR URL is still taken as
  given. A checkout whose origin is not a GitHub repository, and a `--diff` run with no PR
  number, keep the old lookup.
