# pro-gate v0.65.11

## Highlights

- A healthy review no longer warns that its model could not be confirmed. Oracle now names the model field resolvedLabel, and pro-gate read only the old name.
- Nothing else changes: a weak model still warns, and a run that never reports its model still says the model is unconfirmed.
- The fix is in the runtime. A host gets it when its runtime moves to 0.65.11, not when the plugin alone updates.

## Upgrade

Update the marketplace plugin and install the matching 0.65.11 runtime. The opt-in auto-updater follows the promoted plugin version. Existing review records and configuration need no migration.

## Details

- **The renamed field.** At the end of a browser run Oracle logs one `Model selection evidence:` line. Oracle 0.16 and earlier named the model `resolved=`. From 0.17.0 the line reads `requestedKey=…; target=…; resolvedLabel=…; status=…`, and 0.23.1 keeps that shape. pro-gate looked only for `resolved=`, found no field, and so never read `status=` either.
- **What it caused.** Every such line in Oracle's session logs from September 2026 on reads `resolvedLabel=(unavailable)`, nearly always with `status=already-selected`: the Pro model was already chosen, so Oracle did not re-read its label. pro-gate treats that pair as a healthy run, but with no status read it printed "could not confirm the resolved model" and set `model_warn` instead. The status file, ledger and review header showed role-based model text either way, and still do.
- **Why it was seldom seen.** Since late September the installed fork build has nearly always stopped at its prompt-commit check before logging the line, and pro-gate then collected the review from the browser tab. A run with no line rightly warns that the model is unconfirmed. A build that passes the commit check, such as 0.23.1, logs the line on every run, so the false warning would have come back with that upgrade (StartupBros-com/hov-stack#737).
- **The fix.** The parser reads `resolvedLabel=` when the line has it and `resolved=` otherwise, and only from the model line, never the effort line Oracle logs after it. The weak-model denylist, the quiet `already-selected` case and role-based text for `(unavailable)` are unchanged. A model name is recorded only when Oracle reports one, which no logged line has done yet.
