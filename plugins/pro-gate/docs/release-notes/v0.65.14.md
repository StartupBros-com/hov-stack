# pro-gate v0.65.14

## Highlights

- A review on Oracle 0.23.1 records the model ChatGPT's picker showed, such as "Thinking effort Pro", instead of only the label's first line.
- The weak-model warning now sees a model name on the label's second line, and an evidence line with no label field warns of a format change.
- The doctor reads Oracle's version once, with the engine's 20-second limit, and never calls a build it could not read up to date.

## Upgrade

Update the marketplace plugin and install the matching 0.65.14 runtime. The opt-in auto-updater follows the promoted plugin version. Existing review records and configuration need no migration. Records written by 0.65.13 and earlier keep the model they stored.

## Details

### The served model on Oracle 0.23.1 (StartupBros-com/hov-stack#772)

- **What went wrong.** Under the default `current` strategy, Oracle 0.23.1 now reads the model picker's label, and ChatGPT's label holds a line break. Oracle's "Model selection evidence:" record therefore spans two log lines: `resolvedLabel=Thinking effort` on the first, and `Pro; status=already-selected; …` on the second. pro-gate read only the first line, so it took "Thinking effort" as the served model and lost `status=`. On the development host, 8 of the last 10 evidence lines had this shape. A weak model named on the second line could not raise the weak-model warning.
- **The fix.** pro-gate reads the record through its continuation lines, up to the one carrying `status=`, and joins them with a space. A line that opens a new log record (`[…]`) is never joined, so Oracle's effort-picker line that follows stays out. If no `status=` turns up within three lines, the first line is used alone, as before.
- **A format-change warning.** An evidence line that carries neither `resolvedLabel=` nor `resolved=` now warns that Oracle's evidence format may have changed, instead of reading as a healthy run once its `status=` parses. Like every model warning, it never changes the exit code.
- **What this does not change.** The served model is still unverified under `current` (Oracle reports `verified=no`). The `ORACLE_MODEL` default that #333 also raises is untouched.

### The doctor's Oracle version read

- **What went wrong.** The doctor read `oracle --version` twice with a fixed 5-second limit. Under a 5% CPU quota the read takes 7.4 seconds (#735). When the read came back empty, the doctor passed "oracle installed" without a version, skipped the version floor, and then printed "oracle up to date ( = npm latest)" for a build it never read.
- **The fix.** One read feeds the install line, the floor and the release nudge. It uses the engine's limit: 20 seconds, or `PRO_GATE_ORACLE_VERSION_TIMEOUT`. An empty read is now a warning that names the limit and the setting, and the release nudge calls a build up to date only after reading it. The 0.16.0 floor is unchanged.
