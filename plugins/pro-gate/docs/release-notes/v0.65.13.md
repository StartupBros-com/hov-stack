# pro-gate v0.65.13

## Highlights

- A finished review's ChatGPT conversation is now renamed and closed as usual when Oracle saves the answer with its formatting, as Oracle 0.23.1 does.
- pro-gate no longer opens a finished conversation's menu just to find its review title already set.
- Only formatting is ignored: an answer whose text differs from the saved review by a word, number or sentence is still left alone.

## Upgrade

Update the marketplace plugin and install the matching 0.65.13 runtime. The opt-in auto-updater follows the promoted plugin version. Existing review records and configuration need no migration.

## Details

### Why there is no 0.65.12 release

0.65.12 was tagged but never released. The release gate requires the plugin's CI to pass on the tagged commit. There, one assertion in `tests/daemon-reload.test.sh` failed twice in a row, so no draft was staged. That test's two waits stopped polling once the first of their expected log lines appeared, and the check that followed then ran before the daemon had written the rest. Each wait now polls for every line its check requires. The budgets, the sleeps and every assertion are unchanged (StartupBros-com/hov-stack#620). This release carries all of 0.65.12's changes, listed below, and changes no runtime code of its own.

### Changes since v0.65.11

- **What went wrong.** Before it renames, archives or closes a conversation, pro-gate checks that the answer on the page is the review it accepted. It compared the page's rendered text with the saved result byte for byte. Oracle 0.20.0-sb.5 saves rendered text, so the two matched. Oracle 0.23.1 finds the page's copy button and saves the answer as markdown, so a clean review with inline code failed the check as `result-mismatch` and its tab stayed open. The #737 canary showed it: the two sides differed only by eight backticks (StartupBros-com/hov-stack#744).
- **The fix.** Both sides of the check, in the helper and in its in-page twin, now compare a rendered-form key of each text. The key removes only markup that rendering removes: every backtick, asterisk, underscore and tilde, backslash escapes, link targets, table pipes, separator rows and rules, leading heading, quote, bullet and list-number markers, fence lines, and runs of whitespace. A fence's language becomes a line of its own, as the page shows it above the block, and the case of one short line (at most two words) just before a quoted or fenced block is ignored, so a `bash` fence and the page's "Bash" label agree. Words, digits and other punctuation still count, and an empty key never matches.
- **A deliberate widening, and its bound.** This loosens an exact comparison on purpose. Every pair the old check accepted is still accepted, except a text made only of markup, which now keys empty and refuses. Over the 2,815 review results saved on the development host (2,433 distinct texts), the key leaves 2,422 distinct values and none empty; each of the 11 merges joins two results that differ only in blank lines or spacing. Tests keep refusing a markdown result with one changed word, one changed number or one extra sentence, and a changed word on the short line before a quote.
- **What is modeled, not captured.** The real pair in the tests comes from the #737 canary. How the page shows a fenced code block (a language label line, then the code lines) is taken from two saved page captures, Bash and SQL. A fence with no language, or one the page names differently (`sh` against "Bash"), may still refuse and leave the tab open as before. Tables and nested lists have not been seen on a live page.
- **The title check.** The rename step's "already renamed" check read the sidebar title through an unescaped pattern that turned every "s" into a space, so any title with an "s" never matched and the step opened the conversation's menu, then found the title already set. The pattern is fixed and a test now uses a real-shaped title.
