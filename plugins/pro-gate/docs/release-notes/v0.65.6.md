# pro-gate v0.65.6

## Highlights

- On macOS, two runs can no longer both hold one lock after a holder is killed.
- Every engine lock uses the same kernel file lock on Linux and macOS.

## Upgrade

The marketplace plugin update brings the new skill, and the hourly auto-update timer or the
next `/pro-gate` run installs the 0.65.6 runtime.

**On macOS, let in-flight reviews finish before the runtime updates.** Earlier runtimes on a
Mac locked with `mkdir` directories, and 0.65.6 locks with `flock(2)` on files. The two kinds
do not exclude each other, so an old run still going and a new run started beside it on the
same change could both proceed. Once every run on the old runtime has exited there is nothing
left to conflict with. The old lock directories (`*.d`) stay on disk, inert; nothing reads them.
On Linux both versions already used `flock` on the same files, so they exclude each other and
nothing needs waiting for.

A host with neither `flock(1)` nor `perl` now refuses the locked steps instead of running them
unlocked. Stock macOS and every Linux distribution pro-gate supports ship one of the two;
`pro-gate-doctor.sh` names which one it found.

## Details

- **Locks on macOS.** Stock macOS has no `flock(1)`, so `pg_lock`, `pg_lock_n`, the account
  reservation guard, the `--out` guard and the organizer lock fell back to `mkdir` spinlocks.
  A spinlock's owner can die holding it, so each one carried a reclaim step that tried to prove
  the owner dead and remove its directory. After a SIGKILLed owner, about 5 of 100 races still
  admitted two contenders, because the directory a reclaimer removes can already belong to
  someone else by the time it is removed. The fallback is gone. `pg_fd_lock` takes `flock(2)` on
  an open descriptor: with `flock(1)` where installed, otherwise with perl's `flock()` on the
  same inherited descriptor, which is the same kernel call. The kernel releases the lock when
  its last holder exits, so a dead owner leaves nothing to reclaim. Children that inherit the
  descriptor keep the lock, as before
  ([#322](https://github.com/StartupBros-com/hov-stack/issues/322)).
- **Nested locks.** Lock descriptors used to be fixed at fd 9, so a lock taken inside another
  (persisting a result while holding the change lock) replaced the outer descriptor and dropped
  its lock. Each lock now gets its own descriptor: bash's `{var}` allocation on bash 4.1 and
  later, and the first free descriptor from 20 on bash 3.2. Because a lock belongs to its
  descriptor, `pg_lock` on a file the process already holds returns at once instead of waiting
  out its budget on its own lock; a lock file that was deleted and recreated since is a
  different file and is locked afresh.
- **No lock tool.** With neither `flock(1)` nor `perl`, `pg_lock`, `pg_lock_n`, the reservation
  guard, the `--out` guard and the organizer lock refuse with "neither flock(1) nor perl is
  installed; refusing to continue unlocked". The audit ledger still appends unlocked, and the
  auto-updater still runs unlocked and leaves its log untrimmed. The doctor reports a failure
  instead of a pass.
- **Removed.** `PRO_GATE_DIRLOCK_ORPHAN_GRACE` (it only tuned the removed reclaim), the
  test-only `PRO_GATE_TEST_ORGANIZER_NO_FLOCK`, and the reclaim helpers
  (`pg_dirlock_reclaim_dead`, `pg_dirlock_release_own`, `pg_dirlock_owner_count`,
  `pg_dir_age_secs`, `pg_pid_recycled`). Setting the variable has no effect.
