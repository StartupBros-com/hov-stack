# design-rails v0.14.1

## Highlights

- The orphan check now resolves the eight default theme variables that Tailwind v4 defines, so a Tailwind v4 project no longer has them counted against its orphan budget.
- Custom variables and misspelled names that only look like those defaults are still reported as unresolved and still fail the budget.

## Details

Tailwind v4's `theme.css` defines eight default variables that utilities read
through `var()`, sometimes as a nested fallback such as
`var(--tw-duration, var(--default-transition-duration))`. A project that does
not copy `theme.css` into its own source had each of them reported as an
orphan, so a budget of `--fail-on=orphan=0` failed on Tailwind's own names.

The scanner now treats exactly these names as defined:

```text
--default-transition-duration
--default-transition-timing-function
--default-font-family
--default-font-feature-settings
--default-font-variation-settings
--default-mono-font-family
--default-mono-font-feature-settings
--default-mono-font-variation-settings
```

The match is by exact name, not by prefix. A project token such as
`--default-brand-color`, or a typo such as
`--default-transition-timing-functions`, is still an orphan. The tests check
both directions.

`render` and the other `scan` detectors are unchanged in this release.
