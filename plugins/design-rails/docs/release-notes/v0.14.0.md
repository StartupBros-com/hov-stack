# design-rails v0.14.0

## Highlights

- New `render` verb: `design-rails render <url|page.html>` loads a page in headless Chrome and reports what the browser actually paints, not what the source says.
- Four rendered rules: text contrast after alpha and opacity, targets under 24px, text cut off by an overflow-hidden box, and pages that scroll sideways.
- Same `--json` and `--fail-on` gate as `scan`, so a CI step can hold a rendered page to zero findings.

## Details

`scan` reads source: colour literals, utility classes and declared sizes. It
cannot see a 45%-alpha black that paints as a 3.35:1 grey, a wrapper whose
opacity fades every line inside it, or a fixed-height box that cuts off its
last lines. `render` measures those after layout, at 1440x900 and 390x844 by
default (`--viewport=WxH[,WxH]` to change them).

| Rule | Threshold | Notes |
| --- | --- | --- |
| `text-contrast` | WCAG 2.2 SC 1.4.3: 4.5:1, or 3:1 for large text | Text alpha, background alpha and ancestor opacity are composited the way CSS paints them. Disabled controls are exempt. Text over a background image or gradient is counted as not measured, never guessed. |
| `target-size` | WCAG 2.2 SC 2.5.8: 24 by 24 CSS pixels | The spacing, inline and native-control exceptions are evaluated; the equivalent and essential exceptions need intent and are not. Targets under 44px are an advisory count. |
| `text-clipped` | measured layout | Text whose lines straddle an `overflow: hidden` or `clip` edge, on either axis. Ellipsis and line-clamp truncation are listed as intentional, and visually hidden (sr-only) text is exempt. |
| `page-overflow-x` | WCAG 2.2 SC 1.4.10 | The document is wider than the viewport; names the elements past its right edge. |

The verb stays dependency-free. It drives Chrome over
`--remote-debugging-pipe`, so there is no debugging port to attach to. Each
run gets a fresh profile, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` and `TMPDIR`
under one temp root that is removed on every exit. Measurement runs in an
isolated world, so a page that patches `Array`, `JSON` or `getComputedStyle`
cannot steer it. Results come back by value and are only JSON-parsed. Page
strings are stripped of control and bidi-override characters before they are
printed. The test suite renders a hostile page that does all of those things
and checks that it measures exactly like its clean twin.

Chrome comes from `--chrome=<path>`, `CHROME_PATH`, or the usual install
names on `PATH`. `--no-sandbox` is opt-in for containers that need it.

A clean `render` run is not a WCAG conformance claim: it covers four rules on
the pages and viewports given. Contrast follows DOM ancestry, so text over a
positioned overlay can be measured against the wrong ground. Precision on
real application pages has not been measured yet.
