# design-rails v0.14.2

## Highlights

- Colours and arbitrary values inside a comment that spans several lines no longer count as drift. Before, only the comment's first line was skipped.
- The vendor option now reads its value as a glob, so a dot matches only a dot and a stray bracket no longer stops the scan.
- Counts can shift on files with block comments: values inside them stop counting, and code after a closing marker on the same line now counts.

## Details

Changes since v0.14.1, all in `scan`. Both were found by GitHub code scanning
(CodeQL alerts 17 and 20).

- **Multi-line comments.** `scan` blanked comments one line at a time, so in
  a block such as

  ```text
  /*
    old: color #ff0000
  */
  ```

  only the `/*` line was skipped and `#ff0000` was counted as colour drift.
  The same held for `{/* … */}` in JSX and `<!-- … -->` in HTML, Vue, Svelte
  and Astro files. An open block comment now carries on to the lines after it
  until its closer, and code after the closer on the same line is scanned.
  That last part can raise a count: a line that starts with `*/` used to be
  skipped whole, as if it were a jsdoc line, so `*/ const c = "#fff";` hid
  its colour. Re-run `--fail-on` after upgrading; if a budget now fails on
  values that were always live, `--bump` it with a reason, or fix them. Only
  an opener in comment position carries over: at the start of a line or after
  a space or one of `{ } ; , ( ) >`, and not inside a quote. Any other opener,
  as in `"src/*"`, a regex such as `/\/*$/` or JSX text such as `/docs/*`,
  blanks only the rest of its line, as before, so it cannot hide the code
  below it. Ignore directives inside comments work as before.
- **`--vendor` globs.** The flag turned only `*` and `**` into wildcards and
  passed every other character to a regular expression, so `--vendor=src/a.b/**`
  also matched `src/axb/`, and `--vendor=src/[a` stopped the scan with
  `Invalid regular expression`. Every character other than `*` and `**` is now
  literal: `**` crosses folders and `*` stays inside one. A `--vendor` value
  written as a regular expression no longer matches as one.

`render` and the other detectors are unchanged.
