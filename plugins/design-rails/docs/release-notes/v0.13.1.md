# design-rails v0.13.1

## Highlights

- design-rails now ships from the hov-stack repository. Existing installs pick up the move on their next plugin update.
- Run the CLI pinned to a release with pnpm dlx and a hov-stack tag, such as design-rails--v0.13.1.
- Release tags now look like design-rails--v0.13.1. The standalone repository's v0.13.0 tag stays readable after it is archived.

## Details

This is the first design-rails release from `plugins/design-rails/` in
[StartupBros-com/hov-stack](https://github.com/StartupBros-com/hov-stack). The
marketplace entry switches from the old `StartupBros-com/design-rails`
repository to this directory. That repository will be archived with a README
that points here.

Nothing in the scanner, posture checks or authoring commands changed since
v0.13.0, the old repository's last release. What changed is how you get it:

- **Pinned CLI.** npx can't run a package from a repository subdirectory, so
  the README and the skill now pin the CLI as
  `pnpm dlx "github:StartupBros-com/hov-stack#design-rails--v0.13.1&path:/plugins/design-rails" <verb>`.
  An existing CI step pinned to `npx -y "github:StartupBros-com/design-rails#v0.13.0"`
  still names a readable tag, since archiving keeps a repository's tags. The
  posture check recognizes a `design-rails ... scan` step written either way.
- **Repository field.** `package.json` now names hov-stack, with
  `directory: plugins/design-rails`.

One test was not carried over: `test/release-train.test.mjs` checked the old
repository's release workflows, which hov-stack's release chain replaces.
