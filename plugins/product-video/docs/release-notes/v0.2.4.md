# product-video v0.2.4

## Highlights

- A --cdp value without a scheme, such as 127.0.0.1:9223, now gets an error saying it must be a full URL with scheme and port, instead of "Invalid URL".
- A scenario, capture bundle or telemetry file that is not valid JSON now names the file in the error, next to the parser's position.
- tsx, which runs every product-video command, moves to 4.23.15.

## Details

Changes since v0.2.3:

- **`--cdp` error.** `capture` and `narrated:capture` both check `--cdp` with the same
  function. A value without a scheme, such as `127.0.0.1:9223`, used to stop with
  "Invalid URL". It now stops with "--cdp must be a full URL with scheme and port, such
  as http://127.0.0.1:9223". The message does not repeat the value you passed, because a
  value that fails to parse can still hold a password.
- **JSON errors name the file.** A scenario file with a stray comma used to stop with only
  "Expected double-quoted property name in JSON at position 13". It now starts "Could not
  parse <path>:" and keeps the parser's message after it. `narrated:prepare` (and
  `narrated:smoke`) now read the capture bundle and telemetry files through the same
  reader. A missing file still gives the usual "no such file" error.
- **Dependencies.** tsx 4.23.13 to 4.23.15. The `package.json` range for eslint moves to
  `^9.39.5`, the version the lockfile already installed, so this changes no installed
  eslint.

The offline suite (317 tests) passed at this release's commit on one Linux host with
pnpm 11 and Node 24, including new tests that feed each bad input and fail against
v0.2.3's code. Both messages were also checked by running `capture --dry-run` with a
bad `--cdp` value and with a scenario that is not valid JSON. Real captures and the
setup check's render were not run for this release.
