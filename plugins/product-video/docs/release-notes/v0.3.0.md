# product-video v0.3.0

## Highlights

- New RecordedTour composition: cut recordings you already have into one MP4 with title cards, captions, optional audio, and device, full-screen or side-by-side layouts.
- Verification proves by pixels that each clip shows the source frame the plan names, and reports static footage as timing not proven instead of passing it.
- OCR now runs Tesseract on one thread, so verification no longer times out on a busy machine.

## Details

Changes since v0.2.4:

- **RecordedTour.** A plan JSON names local recordings (`.mp4`, `.mov`, `.webm`, `.mkv`),
  scenes and captions. A scene is a title card or a clip in one of three layouts: `device`
  (the recording in a bezel), `full` (edge to edge) or `split` (two recordings side by side,
  each under its own label). Each clip picks a start time and a whole-number speed from 1x to
  8x. Captions are written on the recording's own clock, so they stay put when a clip's start
  or speed changes. Audio tracks are placed at an output time.
- **Commands.** `recorded:prepare --plan` re-encodes each source to constant frame rate H264,
  so frame numbers are exact, converts audio to 48 kHz and writes `resolved.v1.json`.
  `recorded:render` renders it. `recorded:verify` checks digests, codec, size, frame count,
  duration and the audio stream, reads every caption and card title back with OCR, and runs
  the frame match. `recorded:smoke` runs the whole path on generated media with burned-in
  frame numbers.
- **Frame match.** At 20, 50 and 80 percent of every clip, the render's video rectangle is
  compared by SSIM with the exact source frame the plan says is on screen. A point passes at
  0.85 or more, and a neighbouring source frame (two either side) scoring more than 0.002
  higher fails it. On the smoke media, correct frames scored 0.889 to 0.950 and frames five
  or more away at most 0.819. Two cases cannot prove timing and are reported "timing not
  proven", never as a pass: a source that barely changes between frames, and a neighbour
  that looks different in the source but scores within 0.002 of the expected frame. A
  frame repeated by the frame-rate conversion is the same picture, so it may tie.
- **Shared evidence code.** The narrated and recorded verifiers now share one module for
  probing, labelled stills, contact sheets and OCR crops. When Studio hands a composition
  props that name any other known composition, it now falls back to its own default instead
  of trying to parse them; props naming no known composition still fail to parse.
- **OCR on a busy host.** Tesseract's default thread pool could run past the 5-minute command
  limit while renders shared the CPU. Every OCR call now sets `OMP_THREAD_LIMIT=1`.

Not in this release: picture-in-picture, a studio command for RecordedTour, custom font
files, music, sound effects and transitions other than a hard cut.

Checked on one Linux host with pnpm 11 and Node 24: the offline suite (431 tests),
typecheck, eslint with no warnings and prettier. `recorded:smoke`, with audio and with
`--silent`, passed end to end. Each render was H264 yuv420p 1280x720 with 360 of 360
frames, 12.011 s and a 48 kHz audio stream, and all 12 frame-match points matched with
timing proven in every clip scene. The one tie, a 25 fps source's frame repeated at
30 fps, is labelled as a repeat in the report. `narrated:smoke` passed as a regression
check. Real footage has not been through this release's verifier yet.
