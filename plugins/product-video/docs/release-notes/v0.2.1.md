# product-video v0.2.1

## Highlights

- Installing with pnpm 11 now finishes. esbuild may run its build script, and every other dependency's build script stays blocked.
- The setup check now passes on its built-in sample, whose narration fits the part of the capture that reaches the video.
- The four Remotion packages are on 4.0.543 together, so rendering no longer stops on a bundle made by a different Remotion version.

## Details

Changes since v0.2.0:

- **pnpm 11 install.** pnpm 11 blocks dependency build scripts that are not
  approved, and a normal install stopped with `ERR_PNPM_IGNORED_BUILDS` for
  esbuild. `pnpm-workspace.yaml` now approves the build script of the two
  esbuild versions the lockfile resolves and nothing else. The offline suite
  checks that an unapproved build script is still blocked.
- **The setup check, `pnpm narrated:smoke`.** It stopped in two places in
  turn. First, the sample narration was as long as the whole capture, but the
  part of a capture that reaches the video opens once the alignment
  clapperboard has been shown, 1.5 seconds in, and the duration check refused
  the difference. The sample narration now takes its length from the same
  window rule real captures use. That rule is unchanged. Second, dependency
  updates had moved `remotion`, `@remotion/renderer` and `@remotion/cli` to
  4.0.543 and left `@remotion/bundler` at 4.0.518, and Remotion will not render
  a bundle made by a different version. `@remotion/bundler` is now 4.0.543 too.
- **Tests.** Two new offline tests fail on the old code. One checks that the
  sample narration fits the default capture window within the frame-rate
  tolerance. The other checks that every Remotion package in `package.json` is
  pinned to the same exact version, so an update that moves only some of them
  fails CI.

The setup check was run on one Linux host with pnpm 11 and Node 24, installed
the way hov-setup installs it: it rendered and verified a 4.5 second video with
its captions read back by OCR. Real captures were not tried for this release.
`remotion versions` still reports zod 4.4.3 where Remotion's zod types ask for
4.6.7; the setup check passes without that change.
