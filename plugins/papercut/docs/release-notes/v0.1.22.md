# papercut v0.1.22

## Highlights

- papercut now ships from the hov-stack repository. Existing installs pick up the move on their next plugin update.
- papercut list no longer ranks a guard's rewrite receipts: a call the guard rewrote and that then ran is not friction.
- A rewritten command that fails is now logged under its real error, not under the rewrite notice printed before it.
- The hooks print nothing when they have no decision to make, instead of echoing the tool call back.

## Details

This is the first papercut release from `plugins/papercut/` in
[StartupBros-com/hov-stack](https://github.com/StartupBros-com/hov-stack).
The marketplace entry switches from the old `StartupBros-com/papercut`
repository to this directory, and `/plugin install papercut@hov` is
unchanged. That repository will be archived with a README that points here.
Release tags now look like `papercut--v0.1.22`; the old `v0.1.21` tag stays
readable.

It also ships two changes the old repository merged after v0.1.21
(StartupBros-com/papercut#25 and StartupBros-com/papercut#24):

- **Rewrite receipts are quarantined.** When a rewrite guard rewrites a call
  and lets it run, it logs a receipt that says "no action needed"; those
  receipts (`shape-rewrite:<shape>` and a-cost-guard's opaque rewrite) now
  fall under a new `advisory-rewrite` quarantine rule and leave the fix
  queue. A refused rewrite and the guard's real block stay ranked.
  `papercut list --quarantined` shows them beside the junk fingerprints.
- **Failures are keyed on their cause.** The logger skips the
  `[shape-rewrite] rewritten:` line the guard prints before a rewritten call,
  so a rewritten command that fails is recorded under its own error. Records
  already keyed on that line fall under a `rewrite-receipt-line` rule. A
  rewritten script the verifier refuses gets its own
  `guard_blocked:shape-rewrite-refused:<shape>` signature.
- **Quiet pass-through.** The hooks write through a new `lib/hook-output.js`
  and emit nothing on a no-op; the empty body is the "no decision" signal.
- **For the harness's transcript backfill**, the logger exports `record`, and
  its store writer takes a `keepMtime` option so a backfill cannot make a dead
  hook look alive to `papercut staleness`. Nothing in this plugin passes it.
- A shared test helper for the launcher's missing-Python case.

The move itself changes no behaviour. The plugin manifest's `repository`
field, `pyproject.toml`'s `Repository` URL and the README's install lines now
name hov-stack, and a few comments that named the old harness layout use the
current one. What stayed behind is tooling for the old repository, not part
of the plugin:

- **Release scripts and their test.** `scripts/release/` and
  `tests/release-train.test.sh` drove that repository's own release train,
  which hov-stack's release workflows replace.
- **CI helpers.** `scripts/provision-ci-tools.sh` and
  `scripts/check_ci_test_gate.py`, which checked that the old repository's
  workflows ran a test suite. The gate's own deletion condition was "when the
  workflows no longer run a test suite", and hov-stack runs the plugin's
  checks through `tests/ci.sh` instead.
- **Four needles in `scripts/check_no_private_refs.py`.** Its home-path and
  private-project needles are dropped because hov-stack's repository-wide
  public-safety scan covers them. The checker still runs, with its remaining
  needles.

`tests/ci.sh` runs what the old CI workflow ran: the Python and Node test
suites, the install smoke test, the stdlib-only, private-reference and
version-consistency checks, and the launcher packaging checks.
