# sign-it v0.6.1

## Highlights

- sign-it now ships from the hov-stack repository. Existing installs pick up the move on their next plugin update.
- Converting a document can no longer overwrite its own source file, even with --force or through a relative path or symlink.
- An upload that is aborted part-way now frees the drawing page, so your next signature upload is accepted.

## Details

This is the first sign-it release from `plugins/sign-it/` in
[StartupBros-com/hov-stack](https://github.com/StartupBros-com/hov-stack). The
marketplace entry switches from the old `StartupBros-com/sign-it` repository to
this directory. That repository will be archived with a README that points
here.

Changes since v0.6.0:

- **Convert.** The converter now checks whether the output is the source file
  before it picks a converter. An exact, relative or symlinked alias of the
  source is refused, while `--force` still replaces a distinct existing output.
- **Drawing listener.** An aborted or oversize upload releases the listener
  without leaving stale ownership behind, and a late event from that upload
  cannot release the next one.
- **Internal sharing, same behaviour.** Signature persistence, the listener's
  JSON responses and the half-point font shrinking used by date fields and both
  fill paths now each run through one shared routine. Each has its own
  regression test.
- **Docs.** The onboarding-flow spec's status line now says the flow shipped in
  v0.5.0 and records where the build differs from the text.

The skill's offline suite, 220 cases, now runs in hov-stack CI from
`tests/ci.sh` on every change to the plugin.
