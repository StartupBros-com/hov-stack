# hov-stack v0.3.2

## Highlights

- create-verification-skill now tells the verify skills it writes to call an app ready only once it is usable from an empty data folder, migrations and seed data included.
- create-verification-skill now tells its verify skills to report a failure, with the reason, when seed data lacks what a journey needs, never weakening the check to pass.
- create-verification-skill now tells its verify skills to list the setup steps a container or other stand-in did that the real machine will not, and keep those unverified.

## Details

**Get this version.** Run `claude plugin update hov-stack@hov`, then restart Claude Code.
If the hov plugins update themselves, it arrives on its own.

Changes since v0.3.1:

- **create-verification-skill.** Three rules from the upstream pstack skill
  (cursor/plugins `c49b37a`), adopted word for word. The Launch section of a
  generated verify skill must reach a usable state from an empty data dir,
  including migrations and seed data; ready means usable, and a database health
  check can pass while its init scripts are still running. Its readiness examples
  no longer list a port answering. In the feature map, a
  journey whose precondition is missing from the seed data reports a failure, with
  the reason in that feature's `Gotchas`. In the proof step, a proof run in a
  stand-in for the real target lists every setup step the stand-in did that the
  target will not, and those steps stay unverified until a run on the real target
  covers them. These rules were adopted on reading; no generator run has
  exercised them yet.
- **create-verification-skill, maintain-verification-skill.** `UPSTREAM.md` records
  the re-vet and scopes each pin to its own upstream path. The maintain skill's
  text is unchanged.
- **hov-setup.** In `install-release.sh`, the line that creates the temporary folder
  now carries its own `|| exit 1`. The script already stopped there on failure,
  because it runs with `set -e`, so its behaviour is unchanged.
