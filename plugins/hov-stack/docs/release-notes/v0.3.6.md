# hov-stack v0.3.6

## Highlights

- Design help now starts on its own: ask to build a screen from a design, review a page or tidy its spacing, and the pack's design skills apply with no slash command.
- New slash skill /hov-stack:better-interface reviews a whole screen or flow for accessibility, layout, type, colour, copy and UI, with the blockers listed first.
- Builds from a screenshot now state the scale they assumed and call each measured size an estimate, next to the theme step it used.

## Details

**Get this version.** Run `claude plugin update hov-stack@hov`, then restart Claude Code.
If the hov plugins update themselves, it arrives on its own.

Changes since v0.3.5:

- **ui-design, new.** The pack's design skills are slash-only, so until now a plain request
  ("build this from the mockup", "review this page", "tidy the spacing") used none of them.
  ui-design is the one design skill the model starts by itself. It picks the design skills the
  work needs and follows them: accessibility, layout, typography, colour, UI polish, product copy,
  motion and the generic-AI-look check. It names `/hov-stack:prototype`, `/hov-stack:break` and
  the other opt-in jobs at the end of a reply instead of starting them.
  - Building from an image, it states the scale it assumed, writes each measured size as an
    estimate beside the theme step it used, and says the build was not compared with the design
    unless it rendered both.
  - It uses only the steps the project's theme defines, and reads a project design doc
    (`design/DESIGN.md`) first when there is one.
  - It is house-written. Two sentences come from Jakub Krehel's `build-design` skill (MIT).
- **better-interface, new.** Jakub Krehel's whole-screen review from `jakubkrehel/skills`, at the
  same commit as the six `better-*` skills it coordinates (MIT). Run it as
  `/hov-stack:better-interface`; ui-design also uses it for "review this page". It reports
  blockers first and caps the rest at 15 findings.
- **interface-review.** For a review of the whole repository it pointed at `/ux-audit`, which
  the pack does not ship. It now points at `/hov-stack:better-interface`.

What was measured, from `docs/vets/2026-11-17-ui-design-entry.md`. Plain requests, one model
(Sonnet), 4 runs per task, so these are small numbers:

- ui-design started on 15 of 16 design requests, and on none of 12 others: a typo fix, a
  package script and a contributing guide.
- Builds from an image called their sizes estimates in 8 of 8 runs, against 1 of 8 without it.
- A page review found a mean of 10.9 of 11 planted problems, against 10.25 without it, with the
  same one false accusation in 40 checks.
- A review costs about four times as much as before ($0.18 against $0.05 a run), because it
  reads seven skill files.

Known limit: a locally built control can still land on a size the theme lacks (1 of 4 billing
builds sized its toggle off the scale).

The harness checkout also adds the vet fixture, its results and the vet note. None of those are
part of this plugin.
