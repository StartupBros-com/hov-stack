# hov v0.1.5

## Highlights

- A new session no longer starts with every broadcast the host ever carried as unread mail.
- A sender no longer gets its own `*` and `host:*` messages back.
- Mail a session has read, and broadcasts it sent, stay out of its inbox when its title changes.

## Details

A broadcast is now mail only for readers that were around when it was sent. hov records each name's
first contact in a new `names` table; a Claude Code session counts from its own first hook or
command, so a new session that reuses an old title also starts clean. Direct mail is unchanged: mail
sent to a name before that name first appears still waits for it.

Before 0.1.5 a broadcast matched every reader whose read record did not name it. Read records are
kept per name, so each new session, each new title and the sender itself saw the whole broadcast
history as unread, and a session that read under its eight-character id saw that mail again once it
was titled, and so did a session that changed titles. A session now records each read, and each broadcast
it sends, under its eight-character id as well as its title, so a retitle brings back neither.

Upgrade: the first 0.1.5 command on a host creates `names` in one write transaction and fills it with
every name the mailbox already knew (session titles and ids, readers, senders, direct recipients) at
first contact 0, so they keep every broadcast they had unread. A session that already existed keeps
the broadcasts sent since it started. On a copy of a working mailbox (136 messages, 43 sessions) the
first open, which fills the table, took 52 ms against 38 ms for the next, and `hov ls` showed the same
unread counts before and after. A `hov mcp`,
`hov link` or `hov relay` process started before the upgrade keeps the old rule until it restarts.

`hov notify` writes one row on a name's first poll; after that a poll that finds nothing still
writes nothing, so the OMP extension's change gate is unaffected.

Limits: a message carries its sender's timestamp, so a broadcast that crosses a link after a long
outage is not mail for a reader first seen after it was sent, and hosts whose clocks disagree shift
that line by the difference. A broadcast a session sent before 0.1.5 has no such record, so it comes back to
that session after a retitle.

Regression tests run the real script against scratch mailboxes; each new one failed against 0.1.4.
Three existing tests now register their reader before the broadcast they expect.

Fixes [the broadcast backlog issue](https://github.com/StartupBros-com/hov-stack/issues/555).
