# hov v0.1.6

## Highlights

- Mail on disk is private: only your user can read the mailbox folder and its files.
- A host whose Python or SQLite cannot run hov gets one clear line at session start instead of silence.
- The hov skill works without `hov` on `PATH`: it runs the plugin's own launcher.

## Details

Before 0.1.6 the mailbox folder came out 0755 and `mail.db`, its `-wal` and `-shm` files and `hov.log`
0644 under the common umask 022, so any other local user could read message bodies. hov now creates the
default folder 0700 and its files 0600 (SQLite gives `-wal` and `-shm` the database file's mode), and each
hov process narrows, once, a looser folder or file left by an earlier version. A folder named by
`$HOV_STATE_DIR` keeps the mode its owner gave it, since it may be shared on purpose; its files are
narrowed. A mode hov cannot change, say on a file another user owns, is left alone and the hook carries on.
Uninstalling the plugin leaves the folder and its mail on disk.

hov needs Python 3.9 or newer and an SQLite with FTS5. When either is missing, the `SessionStart` hook now
exits 1 with one stderr line that names the Python it ran and the fix, and Claude Code shows that as a
hook error. The prompt and tool hooks log the problem and stay silent, so a session gets one notice
rather than one per tool call. `hov inbox` and the other commands, and the MCP tools, answer with the same
line. An ordinary database error (locked, full) is handled as before. Both requirement paths are tested
by simulation in process; no Python older than 3.9 or SQLite without FTS5 was at hand. The whole suite
passed on Python 3.12.3 and on macOS's stock Python 3.9.6 with SQLite 3.43.2, so the stated floor drops
from 3.10 to 3.9.

The skill now writes every command as `python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/hov" ...`, so a session
that loaded the plugin can use it with no install step and no `hov` on `PATH`.

Fixes [the hardening issue](https://github.com/StartupBros-com/hov-stack/issues/558).
