# hov v0.1.2

## Highlights

- Cross-host mail. `hov link HOST` carries mail both ways over one outbound ssh session, store-and-forward, and a user unit keeps it up. Nothing listens anywhere.
- `hov ls` shows each link's state, and `hov send` to a host no link has reached says the message waits here until one does.
- `hov --version` reads the VERSION file, and 21 relay tests run two real `hov` processes against each other over a pipe.

## Details

The initiating host (the hub) runs `hov relay` on the peer through `ssh -T` and speaks newline-delimited
JSON to its stdio. Every row crosses once per peer: the receiver inserts the row and its inbound mark in
one transaction, commits, and only then acks; the sender records the ack, and that record doubles as the
echo guard, so a row received from a peer is never offered back to it. A row whose ack is lost is offered
again after thirty seconds and the receiver keeps one copy. Mail written while the link is down waits in
the local mailbox and crosses when the link returns, which replaces the reverse ssh path the decision
record left open.

A hub forwards to a peer what is addressed to that peer or to `*`; a leaf forwards to its hub everything
not addressed to itself, so two leaves reach each other through the hub. `*` now means every session on
every linked host. The link refuses a peer that announces the hub's own label, a peer on another protocol
number, and a row that fails validation; it skips login banners and runtime-manager warnings that arrive
before the peer's hello, and logs the remote's stderr when the remote command ends before saying hello.

`systemd/hov-link@.service` is the user unit, one instance per peer alias. It carries the `PATH` the user
manager lacks, and multiplexing is pinned off on the ssh command, so a shared master from an interactive
shell never carries or outlives the unit's session.

Also fixed: `hov --version` printed a constant that lagged the VERSION file.
