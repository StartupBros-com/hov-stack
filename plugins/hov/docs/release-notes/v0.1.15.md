# hov v0.1.15

## Highlights

- The line hov adds after Claude Code's ListAgents, or after a SendMessage that reached nobody, now arrives when another session holds the mailbox's write lock. In 0.1.14 a locked mailbox dropped that line.

## Details

0.1.14 added one line after Claude Code's own ListAgents (how many finished sessions that list leaves out) and one after a SendMessage that reached nobody (what the session is and the two commands that reach it). The PostToolUse hook worked the line out first and opened the mailbox second. When another session held the mailbox's write lock for longer than the hook waits (`HOOK_BUSY_MS`, 2 s), the hook logged `hook-error ... err=database is locked` and ended with no output, so the line went with the mail.

The mail can wait: nothing is claimed under the lock and the next hook hands it over. The line cannot: it explains one tool call, and that call runs this hook once. It also needs no mailbox, only the agents listing.

The hook now writes the line when the mailbox step fails, then logs the error as before.

Unchanged under a locked mailbox:

- No mail is read or claimed. The next hook delivers it.
- One `hook-error` line goes to the log and the hook exits 0.
- A tool call with no line (anything but ListAgents and an unreached SendMessage) still gets no output.

How often this happened is not known. The host this was found on logged 451 locked-mailbox hook errors in one day with about 30 sessions sharing the mailbox. The log does not say which tool call each one followed, so the share that cost a line was not counted. The 0.1.14 acceptance sessions each had a mailbox of their own, which is why they did not show it.

One test added (`test_reach.py`, thirty-three): with a healthy listing and the mailbox locked by another writer, both lines arrive, a Bash call still says nothing, three errors are logged, no mail is in the output, and the next hook delivers the mail. It fails on 0.1.14's hook.
