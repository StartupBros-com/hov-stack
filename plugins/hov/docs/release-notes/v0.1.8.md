# hov v0.1.8

## Highlights

- A machine with no python3 on its PATH now gets one line at session start saying hov needs Python 3.9 or newer, instead of a hook error on every prompt and tool call.

## Details

hov 0.1.6 gave a host whose Python or SQLite cannot run hov one clear line at session start. That covered a
Python older than 3.9 and an SQLite without FTS5, but not a host with no `python3` at all. There, each of hov's
`SessionStart`, `UserPromptSubmit` and `PostToolUse` commands exited 127 with `/bin/sh: 1: python3: not found`.
Claude Code shows any exit other than 0 or 2 as a hook error, so the session got one on every prompt and every
tool call.

Each of those three commands now checks for `python3` before it runs hov. With none on `PATH`, `SessionStart`
prints `hov needs Python 3.9 or newer, and no python3 is on PATH. Install one or put it first on PATH.` and
exits 1, and the prompt and tool commands exit 0 and print nothing. With `python3` present, each runs
`python3 -I "${CLAUDE_PLUGIN_ROOT}/scripts/hov" hook <Event>` as before. The `Stop` command is unchanged: it
already exited 0 when `python3` was missing.

On a Mac without the developer tools, `/usr/bin/python3` is a stub that opens an install dialog. The check finds
it, so such a Mac behaves as it did in 0.1.7.

Two new tests in `test_state.py` run the commands from `hooks.json` through `sh -c`, as Claude Code does. With an
empty `PATH`, `SessionStart` exits 1 with that one stderr line and the other two exit 0 with empty stderr; the
0.1.7 commands each exit 127 there. With a stub `python3` on `PATH`, each command still hands its event and its
stdin to the hook. The whole suite, 153 tests, passed on Python 3.12.3.

The change is hov-stack#568.
