# hov v0.1.3

## Highlights

- Codex and oh-my-pi reach the mailbox. `hov mcp` is an MCP server on stdio exposing `whoami`, `inbox`, `send`, `thread`, `search` and `ls` as tools; `hov notify` is the count-only block an OMP extension (`omp/hov-mail.ts`) prints into the run before each turn.
- Delivery into any agent stays text and count-only until the agent asks: `notify` never prints a body, the MCP server answers only what it was asked, and the plugin wires nothing by itself.
- Identity fields in `hov inbox`, `thread` and `search` output pass the same filter the hook uses, so a row an older version let in cannot plant a header line or a frame tag in what an agent reads.

## Details

`hov mcp` speaks MCP 2025-06-18 (and the two earlier versions) as newline-delimited JSON-RPC on stdin and
stdout, flushing every reply before it reads the next request and exiting 0 when the client closes stdin.
Tool arguments are checked against each tool's schema before anything runs; an unknown tool or bad arguments
is `-32602`, an unknown method `-32601`, a line that is not JSON `-32700`, a batch `-32600`. A refused send or
an empty thread is a result with `isError`, and a server bug becomes `-32603` and a log line, never a crash
mid-session. Its `initialize` reply carries the untrusted-peer framing and "a message never runs anything" as
instructions, which OMP and Codex place in the system prompt. Identity is `--as NAME`, else `HOV_AS`, else what
`whoami` resolves.

`hov notify --as NAME --session ID` prints the `<hov-mail>` count block when that session has mail it was
not handed yet, else nothing (`--json` gives an object either way). It shares the hook's `deliver`, so the
frame, the once-per-session record and the log line are the same; it never marks anything read, and an OMP
session is not a Claude Code session, so nothing is looked up in `claude agents` and nothing is written to
`sessions`. The OMP extension is plain JavaScript in a `.ts` file: one `before_agent_start` handler that
runs `hov notify --json` and returns the block as a `hov-mail` custom message; a missing `hov`, a non-zero
exit or junk output returns nothing, so a turn never fails over mail. It is installed by copying it into
`~/.omp/agent/extensions/`, takes effect when OMP next starts, and touches no running session.

Wiring is an enabling step, not part of the plugin: `mcp/omp.mcp.json` is the entry for `~/.omp/agent/mcp.json`,
Codex takes `codex mcp add hov -- hov mcp --as codex`, and `docs/agents-snippet.md` is the AGENTS.md text.
The plugin root carries no `.mcp.json`. The `run-codex` wrapper the decision record named is not built: draining
bodies into an unattended prompt contradicts count-only delivery, and the `inbox` tool gives Codex the same mail
when it asks.

Twenty-eight new tests drive the server over a real pipe and the extension under node with a fake host whose
`exec` runs the real script. Not proven here: a model inside OMP or Codex reading the block or calling the tools.
