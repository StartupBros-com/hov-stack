# hov v0.1.14

## Highlights

- hov send now restarts a finished Claude Code session so it reads direct mail from another agent, on a fixed sentence of hov's own and within the wake limits. It can be turned off.
- New hov ask: one question to a read-only copy of any session's saved conversation, finished or running. It prints the answer and restarts or interrupts nothing.
- After Claude Code's ListAgents, or a SendMessage that reached nobody, hov adds one line: how many finished sessions that list leaves out, and the two commands that reach them.

## Details

**This release lets one agent start a turn in another agent's finished session.** Until now hov only woke a session that still had a process. Read "What a restart can and cannot do" below before updating a host where that matters, and set `HOV_RESTART=0` in the environment of any session that should never restart another.

### The gap

A background Claude Code session that finishes its turn keeps an idle process for about an hour. While it does, Claude Code's own SendMessage reaches it and so does hov's idle wake. Then Claude Code stops the process. The session is still listed by `claude agents --json --all` (state `done`, no `pid` or `status`) and still shown in the agents view, but SendMessage answers `No agent named '...' is reachable`, ListAgents does not show it, and mail left for it by `hov send` waited for a start nobody asked for. 0.1.13 listed those sessions and gave them no address.

### What `hov send` does now

After storing the mail, `hov send` looks each recipient on this host up in one `claude agents --json --all` listing and acts on what it finds:

| Recipient | What happens |
| --- | --- |
| Running, mid-turn | Unchanged: its hook hands the mail over at its next tool call. |
| Running, idle, watcher armed | Unchanged: the idle wake starts a turn. |
| Running, idle, no watcher | The mail waits for its next prompt. New: `send` says so on stderr and prints the name Claude Code's SendMessage takes for it. |
| Finished: `done`, no process | New: `send` restarts it to read the mail. |
| No process and not `done` | Not restarted. The mail waits and `send` says why. |
| Finished, launch folder gone | Not restarted (Claude Code refuses). The mail waits and `send` says why. |
| Two or more sessions with no process share the name | None restarted. `send` lists their 8-character ids. |
| On another host | Unchanged: the mail crosses the link. Nothing is restarted there. |

`send --json` adds a `reach` list with one entry per recipient it acted on or explained: `to`, `session_id`, `action` (`restarted` or `none`) and `why`.

### What a restart can and cannot do

- It runs `claude --bg --resume <session id> <text>` from the session's launch folder, with stdin closed and a 20 s limit. Claude Code continues the session under its own id, name, permission mode and model.
- The text is one fixed sentence written by hov. The sender's subject and body are never an argument of that command. They stay in the mailbox and reach the restarted turn the way all mail does: in full, framed as untrusted peer text, in a session that asks for permission; as a count and the senders in a session that bypasses permissions, which then runs `hov inbox`.
- It grants nothing. The restarted session runs under its own permissions and its own task. Observed here: asked to do something inside its original task, a restarted session did it and replied; asked for a file edit outside its task, another declined and said why. A session that asks for permission waited at the prompt for its user.
- Only the `hov send` command restarts, and only for direct mail that would wake an idle session: not kind `status`, not importance `low`, not a broadcast, not the sender's own. The MCP `send` tool and mail arriving over a link restart nothing. Every restart is therefore one visible command, which a host's own hooks can count.
- Each restart is charged to the recipient's wake budget, shared with the idle wake (one per 30 s, 12 an hour, 48 a day; `HOV_WAKE_COOLDOWN_S`, `HOV_WAKE_CAP`, `HOV_WAKE_DAY_CAP`), before Claude Code is run. A refused or hung restart is charged too, so a sender cannot retry past the limit.
- Only a session in state `done` with no process is restarted. One waiting on its user or one that died mid-turn is left as the agents view shows it.
- Claude Code before 2.1.257 starts a copy under a new id instead of continuing. hov reads `claude --version` first and restarts nothing on an older or unreadable version. If a copy is started anyway, hov stops it with `claude stop` and reports that.
- `HOV_RESTART=0` in the sender's environment turns restarts off; the mail is still stored.
- Cost: the restarted session loads its whole conversation, as any resumed session does.

### `hov ask`

`hov ask SESSION "QUESTION"` (`--json`, `--timeout SECONDS`, `-` for stdin) puts one question to a copy of a session's saved conversation and prints the answer. `SESSION` is a name, an 8-character id or a whole session id on this host, finished or running.

- The copy is `claude -p --resume <id> --fork-session --no-session-persistence --tools Read,Grep,Glob --strict-mcp-config --permission-mode dontAsk --max-turns 20`: it is not saved, and the original is not restarted, interrupted or told. It runs in the session's launch folder (the caller's when that folder is gone) and can read files under it; under `dontAsk` a read anywhere else is refused unless the host's permission rules allow it.
- hov's own hooks do nothing inside the copy (`HOV_HOOKS=0` in its environment), so the original's mail is not read or marked, and no watcher arms.
- The copy cannot run a command or send anything, so an ask cannot start another ask or a restart.
- The question is framed as untrusted peer text. The answer is what the session believed when it stopped, not a fresh check.
- stderr carries one line with the seconds and input tokens the copy took. Seen here: 10.9 s and 56,000 input tokens for a short session answered in one turn, about 55 s and 110,000 when the copy also made a tool call; earlier copies of long sessions took 62 to 149 s and 96,000 to 332,000 input tokens.
- Exit 0 with the answer, 1 when the copy gave none, 2 when hov cannot pick one session.

### Rows and lines

- A `finished` row in `hov ls --all` now carries `addr` (its title when no other listed session holds it, else its 8-character id), `unread` and `restart` (false when its launch folder is gone; `restart=no` in the text form). `send_to` stays null. Its mail is counted on that row, no longer on a second `mailbox` row. A session that still has a process is no longer shown as finished.
- The PostToolUse hook adds one line of hov's own after `ListAgents` (how many finished sessions that list leaves out, with the `ls --all`, `send` and `ask` commands) and after a `SendMessage` whose response says nobody was reachable, when the name belongs to a session with no process (what it is and how to reach it). Nothing a peer wrote is in either line. Only those two tool calls cost a listing, which is given 2 s, taken out of the hook's wait for a locked mailbox; a listing that hangs or fails adds nothing and costs no mail. `HOV_REACH_NOTES=0` turns both off.
- `hov inbox` ends with `You are <address>. Reply: <command>` when the newest message can be replied to, as the full hook block already did.
- `HOV_CLAUDE_CMD` names the Claude Code command (default `claude`). Where `HOV_AGENTS_CMD` or `HOV_AGENTS_ALL_CMD` is overridden and `HOV_CLAUDE_CMD` is not set, hov runs no Claude Code, so a test cannot restart or copy a real session.

### Observed

On 2026-11-25 with Claude Code 2.1.332, on throwaway background sessions:

- A session with no process, permissions bypassed, its worktree removed: `hov send` restarted it in under a second; it read the mail, answered and replied to the sender in 52 s, and declined a file edit that was outside its task.
- A request inside the session's task was carried out and answered in 12 s by a session idle with a live process (the idle wake), in 35 s by one with no process (the restart), and in 25 s after a SendMessage by one whose watcher had been retired by hand, where `hov send` alone left the mail waiting and said so.
- A session with no process that asks for permission was restarted with the mail in full, then waited 57 s at the permission prompt until its shell command was approved.
- `hov ask` to a session with no process and no launch folder answered in 10.9 s and left the session as it was. Asked to read a file under its folder, the copy read it (52.9 s and 113,000 input tokens for the two turns).
- `hov ask` to a session idle with a live process answered in 55.7 s for 106,000 input tokens. The session's process, listing row and saved conversation were unchanged. The copy's read of a file outside its folder was refused.
- Both hook lines appeared inside a session running this version: one after its `ListAgents`, one after its `SendMessage` to a finished session. A SendMessage that reaches nobody is an ordinary tool result (`success: false`), so PostToolUse runs for it.
- The restarted process held none of the sender's session variables.

Not observed: a restart on Claude Code between 2.1.257 and 2.1.331, and a restart across hosts (there is none).

### Tests

Twenty-eight new tests in `test_reach.py`, each against a fake Claude Code that logs every call, with planted negatives for the rules above: the sender's text in no argument of any call, no listing for any other tool call, no `claude` from `PATH` under an overridden listing, nothing restarted that has a process or is not `done`. Three `test_hov.py` tests now assert the new row fields.

The change is tracked in hov-stack#902 and hov-stack#844.
