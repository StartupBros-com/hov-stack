# hov v0.1.13

## Highlights

- hov ls --all now lists the sessions that have finished, so an agent told to reach one can see it ended and where its work is: when it last ran, its repository and branch, the pull requests linked from its output, its saved conversation and the files it wrote. A finished row has no address, because a finished session cannot be messaged.

## Details

A finished background session had no row in `hov ls`, because `claude agents --json` leaves finished sessions out. A session told to ask a finished one could not tell it had ended or been renamed, so it took a running session with a similar name for it, or hunted through saved conversations for what it left. In one 70-hour sample of real lookups, 6 of 76 wanted something only a finished session could answer, and none of the six could get it from a list.

`hov ls --all` (and `all: true` on the MCP `ls` tool) now reads `claude agents --json --all` as well and adds one row per session it shows as `done` that the default listing leaves out, newest first, after the sessions and mailboxes. Without `--all` the output is unchanged.

A finished row carries facts and pointers only:

- `kind: "finished"`, `session_id`, `name` (its title, or null when the identity rules refuse it), `state: "done"`, and null `addr`, `send_to` and `status`.
- `last_active`: the timestamp of the last entry in its saved conversation. The job record's own update time is not used: on the host this was built on it was more than an hour after the last entry for 20 of 48 finished sessions.
- The location fields of a session row, with two differences. The branch is the one its transcript recorded last, the branch it was on when it last ran. And when its worktree was removed after its merge (`dir_from: "gone"`), the repository and main checkout come from the checkout the worktree sat in, so `--repo` still finds it: 16 of 17 such sessions on that host.
- `pr_links`: the newest five pull requests Claude Code linked to its background job from what the session printed, as `owner/repo#N`, and `pr_links_total`. These are not only pull requests it opened: of 36 links sampled from 10 finished sessions, 5 were on the branch the session ended on, and all had the same author, so authorship cannot tell an opened pull request from one it only mentioned.
- `transcript`: the path of its saved conversation.
- `deliverables_written`: the newest five files it wrote with a write tool (Write, Edit, MultiEdit, NotebookEdit) into a `.claude/deliverables/` folder that are still on disk. A call whose result was an error does not count, nor does a file it only read or a write call quoted in a tool result or in text. `deliverables_read` says how much was read: `whole`, or `tail` when only the end of a longer transcript was, so a short or empty list may not be everything it wrote (`wrote=N+` in the text form).

Nothing a session or the operator wrote as prose reaches a row. Of the job record only the pull request links are read, never its prompt, current step, result or link titles; of the listing only the id, title, launch directory and state; of the transcript only timestamps, directories, branches and the paths of write tool calls. hov withholds message bodies from sessions that run without permission prompts so that one agent's words cannot steer another, and a summary in the list would carry agent-written text past that.

Transcripts can be large (7.25 GiB for the 44 finished sessions with one on that host), and a first listing there that read up to 256 MiB of uncached transcripts took 26 s. So each transcript is read from its end, 32 MiB at most, newest session first, for about 2 seconds a call; one read can run past that (`HOV_FINISHED_READ_SECONDS` and `HOV_FINISHED_TAIL` override the two limits). A row past the limit shows `deliverables_written: null` (`wrote=?` in the text form, with a line saying to run it again). What was read is kept in `finished.json` in the mailbox folder, keyed by each transcript's size and modification time, so the next call reads only what changed. A 32 MiB tail held the newest such write for 17 of the 19 sessions there whose transcript holds one (8 MiB: 14; 128 MiB: 18). On that host `hov ls --all` took 2.8 s with the cache filled and `hov ls` 1.4 s.

On that host the four finished sessions behind this change each appear as finished rows, apart from the running session with a similar name, and three point at the report each wrote.

`HOV_AGENTS_ALL_CMD` overrides the `--all` listing as `HOV_AGENTS_CMD` overrides the default one. When only `HOV_AGENTS_CMD` is set, `--all` lists no finished sessions rather than reading the real host's.

Five new test functions in `test_hov.py` and one extended in `test_mcp.py`, with planted negatives for each rule above. Each guard was also broken in turn in a scratch copy, and every one of the 16 breaks failed a test.

The change is tracked in hov-stack#894 and hov-stack#844.
