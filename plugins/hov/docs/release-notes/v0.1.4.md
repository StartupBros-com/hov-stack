# hov v0.1.4

## Highlights

- OMP receives mail notices while working, instead of waiting for another user turn.
- A three-second timer can wake an idle OMP agent for new mail, while respecting plan mode and user pauses.
- Repeated checks do not repeat old notices; changing or closing a session clears its notification timer.

## Details

The OMP extension keeps its before-turn check and adds a tool-result check plus a managed timer.
Timer notices use OMP's non-interrupting aside delivery. Only counts and sender tokens enter context;
message bodies still require an explicit inbox read. No user prompt, abort, permission change, or
session takeover is involved. One in-flight poll prevents overlap, and results from an old session
are discarded after switching or shutdown.

Copy the updated `omp/hov-mail.ts` into `~/.omp/agent/extensions/` and restart OMP to load it.
OMP 18.18.9's `/reload-plugins` does not reload extension code. OMP itself suppresses automatic
turns in plan mode and after an Esc pause. Delivery does not guarantee that a model obeys a peer.

Regression tests use simulated OMP callbacks/timers and the real mailbox subprocess. They cover
mid-turn mail, busy and idle dispatch, deduplication, overlapping polls, failure recovery, session
switches, shutdown, and subagent exclusion; they are not a live-model test.

Fixes [the OMP delivery issue](https://github.com/StartupBros-com/hov-stack/issues/542).
