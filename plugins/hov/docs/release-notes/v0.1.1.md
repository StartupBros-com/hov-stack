# hov v0.1.1

## Highlights

- Mail is no longer injected at session start. Delivery waits for the first prompt or tool call, which state the permission mode, so a bypass session only ever gets the count.
- The session-name cache is now committed on every lookup, so `hov whoami` and a mail-less session start keep the name they resolved.
- Nineteen tests, including the captured session-start payload shape and a planted negative for the old fail-open.

## Details

Claude Code's `SessionStart` hook payload carries no `permission_mode`. Version 0.1.0 read a
missing mode as "full", so a session launched with permissions bypassed and mail already
waiting got message bodies at session start, where the same session gets a count-only block
at `UserPromptSubmit` and `PostToolUse`. This showed up on two hosts the day the plugin was
loaded through settings rather than `--plugin-dir`. An event whose payload states no mode now
delivers nothing and records nothing; the first event that states the mode delivers in it.

The new test exposed a second fault: `resolve_session` wrote the cached session name and the
lookup throttle without committing, on a connection that runs implicit transactions. They
persisted only when the caller committed something else afterwards, which the hook did on a
delivery and `hov whoami` never did. The function now commits its own writes.

README, the skill and the plugin manifest no longer say mail arrives at session start.
Umbrella issue: [hov-stack#529](https://github.com/StartupBros-com/hov-stack/issues/529).
