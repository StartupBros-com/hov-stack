# hov v0.1.12

## Highlights

- hov ls --json now gives each running session the exact name to pass to SendMessage. A stopped session gets none, so an agent can tell who can still be messaged.

## Details

`hov ls --repo NAME --json` (0.1.11) tells a session which peers work in a repository and on which branch. It did not say how to address the one it chose, or whether that session was still running to receive anything.

Each session row from `hov ls --json` now carries `send_to`:

- the session's title, when it has one the identity rules accept and the session has a running process. That is the name `SendMessage` takes as `to`. On the host this was built on, it matched the name in Claude Code's own peer list for 28 of 28 running sessions.
- null when the session is not running. `claude agents --json` gives a running session a `status` (`busy`, `idle`) and a stopped one none, and Claude Code's peer list shows only the running ones: 5 of 5 sessions hov listed with no `status` were absent from it. `hov send` to the row's `addr` still leaves mail, which the session gets only if it runs again.
- null when the title holds a control character, `<` or `>`. That session goes by its 8-character id in hov, which is not a `SendMessage` name.

Mailbox and link rows carry `send_to: null`.

A session that has finished is not in `hov ls` at all, as before: hov reads `claude agents --json`, which leaves finished sessions out. `claude agents --json --all` lists them with `state: done`. So a null `send_to` marks a session that is listed but stopped, and a finished one shows by its absence.

Two sessions with the same title share a `send_to`. `SendMessage` then needs the short reference Claude Code's peer list prints beside each name; hov cannot supply it, because it is not in `claude agents --json`.

The text form of `hov ls` is unchanged: the name is already the part of the address after the host, and a stopped session already shows no `busy` or `idle`. `hov ls --help` and the MCP `ls` tool's description now say what a missing status means.

The `status` field belongs to Claude Code and is not documented. If a later version stops writing it, every `send_to` reads null rather than naming a session that cannot be reached.

No new test functions. Three existing tests now also assert that a running titled session's `send_to` is its title, that a mailbox has none, that a titled session with no status has none, and that a running session with a refused title has none and its title appears nowhere in the JSON.

The change is tracked in hov-stack#844.
