# Harness Runbook

How this machine's Claude Code harness is wired, and the standing decisions that
govern it. Detail docs live in `harness/` — grep there before changing anything.
Always-on behavioral rules stay in `CLAUDE.md`; this file is the on-demand
reference (linked from CLAUDE.md by path, deliberately NOT `@imported` — imports
expand eagerly into every session's context).

## Doctrine

- [Two homes](harness/cc-two-homes-decommission.md) — canonical harness = WSL `~/.claude` (stable parts symlinked into `~/hov-stack`); Windows `.claude` is a break-glass stub; consumers point/read, never copy. Drift: `scripts/harness-doctor.sh` (on demand). An Anthropic-hosted cloud session loads none of `~/.claude` (user settings, hooks, CLAUDE.md, memory, skills), so a cloud adoption must first decide which guards get re-homed into the repo (`docs/vets/2026-09-28-groundtruth-self-coordinating-agents-harness-vet.md`).
- **ccflare gateway: one machine-wide dependency, owned here** — every Claude Code request (settings `ANTHROPIC_BASE_URL=http://127.0.0.1:8788`; `ccflare-guard.mjs` listens on 8788 and fronts the better-ccflare server on 127.0.0.1:8789) and the direct-Codex pool rung ride it, so a gateway outage is a fleet outage. Supervision (configured, not crash-tested): system unit `ccflare-stack.service` (enabled, `Restart=always`, drop-ins under `ccflare-stack.service.d/`); its runner `~/.config/better-ccflare/run-ccflare-stack.sh` restarts server, guard and tunnel with backoff and exits 75 after repeated fast failures so systemd restarts the unit; `RUNNER_RSS_*` drop-ins recycle the upstream on a memory threshold. The unit requires the ssh tunnel to the AI gateway host (`AI_GATEWAY_TUNNEL_REQUIRED=1`), so that host is inside the outage set. Health: `curl -s 127.0.0.1:8788/health` and `systemctl status ccflare-stack`. Known costs: a systemd unit that runs Claude does not inherit the settings.json base URL and must set `ANTHROPIC_BASE_URL` itself; the base URL disables Remote Control; a step whose thinking arrives as empty deltas for more than about 450 s is aborted by the gateway's meaningful-progress policy and retried (`claude-loop.sh` sidesteps it with `--thinking-display summarized`, better-ccflare#356).
- [MCP architecture](harness/cc-mcp-architecture.md) — MCP lives in `~/.claude.json` + per-repo `.mcp.json` (settings.json `mcpServers` is ignored); http→global, stdio→per-repo because ~20 concurrent sessions; no stdio exception since 2026-09-21; doctor check 3 warns on any global stdio server. Telegram MCP removed from global 2026-07-17 (real use is the bot-token / `api.telegram.org` path, not the MCP server).
- [On-demand data CLIs](harness/data-source-clis.md) — GA4 `ga4` (reports + Admin API passthrough, existing GSC key file); Discord `discord-cli` (named reads, message writes, `api METHOD PATH` passthrough to the v10 REST API); Resend `resend-cli` (official CLI behind an exact-record BWS wrapper). The shell guard asks, never denies, on Discord send/edit/delete, on `api` with any method but a literal `GET`, on any verb/method it cannot read statically, and on Resend send/write/destructive paths however the confirm flag is spelled. The Discord MCP server stays a project opt-in; Shadcn MCP is retired from default startup. Doctor check 31 includes suffixed grants and project approvals; the targeted migration plans by default and applies only in a quiet activation window. Keep active session processes and webhook alerts intact.
- [Worktree fleet hygiene](harness/worktree-fleet-hygiene.md) — wt-sweep.sh policy; removing a worktree keeps the branch; don't lower `cleanupPeriodDays`.
- [wt-sweep triage pattern](harness/wt-sweep-triage-pattern.md) — two-stage disposal: conservative sweep → content-verified triage (`scripts/branch-triage.sh`) → bundle+delete.
- **Merge-anchored closeout** (`scripts/wt-done.sh`, issue #589; defect narrative and measurements in the script header) — `gh pr merge --squash` + `delete_branch_on_merge` leaves a branch's commits reachable from no durable ref, so Claude Code's Agent View refuses to close the worktree (upstream anthropics/claude-code#78355) and wt-sweep scores shipped work as unique. No content heuristic can fix it (`--cherry-pick` fails on squash, tree equality dies once main moves); the only proof is the PR's own record, one of three exact identities. **A**: `headRefOid == HEAD`. **B**: `git diff <mergeCommit> HEAD` is empty; wt-done then `git reset --soft`s the branch onto the merge commit (soft, never hard: zero files touched). **C**: the tip is an ancestor of the merged head (more commits landed after this worktree pushed; the PR is found via GitHub's commit→PR endpoint when branch names differ; only PRs merged into the default branch count; the merge commit must be an ancestor of `origin/<def>`; a shallow clone asks GitHub's compare and accepts only `ahead 0`/`identical 0`, #1369). A and C cannot move the pointer; once `ls-remote` shows `refs/pull/<N>/head` names the merged head, wt-done records it at `refs/remotes/pr-merged/<branch>` in one `update-ref` (`scripts/lib/wt-anchor.sh`), which satisfies Claude Code's close gate `git rev-list HEAD --not --remotes`. Anchors exist only for proven-merged PRs (no blanket `+refs/pull/*/head` refspec: Claude Code's `cleanupStaleAgentWorktrees` uses the same predicate); an anchor lives as long as its branch and is pruned as an orphan by wt-done and wt-sweep; both scripts exclude `pr-merged/*` from the unshipped count and refuse to run without `wt-anchor.sh`. A proof covers only the tip it was computed for: wt-done re-checks branch, HEAD and status before printing `WT_DONE_PROOF=head` or removing, and wt-sweep (via `--reconcile-only`, which prints that line) requires HEAD unchanged and a clean tree before disposing, so a late commit or edit is kept; a sweep that cannot read the unshipped count skips the worktree. `ExitWorktree` is a different check and not a required step. A full-mode run also activates the canonical checkout (since #909): if the merge commit is not yet an ancestor of its HEAD it runs `launchpad-freshen.sh --repo` and prints `activation: checkout current` or `checkout not current` (proves checkout currency, not service restart, #1883). `--reconcile-only` and dry-run never activate. An already-reconciled branch looks up the PR that merged its tip and activates from that merge commit (#1372). After a printed `!! activation:` line, the line itself names the reason; if the freshen refused to overwrite local changes in the checkout, ask the operator for that one decision and re-run `wt-done` yourself (`CLAUDE.md` carries the same rule). Before its first write wt-done runs `scripts/wt-unlock.sh` on the worktree, and wt-new runs it on the checkout before its fetch and `worktree add` (dotfiles#1590): a git lock (`index.lock`, `packed-refs.lock`, `refs/**/*.lock` in the worktree gitdir and the common dir) is removed only with staleness proof (mtime older than 60 s, no process holds it open, no `git` process on its scope in three probes a second apart, where a worktree-private lock scopes to its gitdir and checkout, a shared lock in the common dir to the common dir plus every registered worktree, and the main checkout's index.lock to the common dir plus the main root from whichever checkout runs the helper, all read through `scripts/lib/proc_liveness.py` and its `--comm git` filter; a probe that sees a git, or cannot answer, keeps the lock); every other lock is kept with its reason printed, and the next git write fails on it as before. dcg never reads inside a script, so the helper is the sanctioned path for a lock a killed probe left; `GIT_OPTIONAL_LOCKS=0` and `diff.autoRefreshIndex=false` on the scripts' read-only probes (dotfiles#1954) are what stop new ones, and the hook-side probes follow in a separate port (issue #241).
- [Evidence regime](harness/evidence-regime.md) — the Ceremony Test (in `CLAUDE.md`); zero-run-green is FAILURE (`scripts/gate-check.sh`); No-Claim Boundary + planted negatives on every work spec; the closed negative-evidence outcome set incl. `VOID`/`NO_EVIDENCE` with a mandatory do-not-retry predicate; `bin/ab-pair.sh` for any comparative perf claim.
- [RLM external state — declined](harness/rlm-external-state-decision.md) — standing decision 2026-08-11: do not adopt a persistent-kernel/RLM external-state layer or a "parse programmatically, don't read big files" CLAUDE.md rule (two bake-offs tied at 100%; the kernel arm used more context). Do not re-propose; do-not-retry predicates in the note. Note: `ab-pair.sh`'s 5% cv gate cannot adjudicate agent-scale workloads (issue #367).

## Autonomy & permission model

The enforced tiers ARE `~/.claude/settings.json` `permissions.{allow,ask,deny}` + the root managed floor (check 12) + the git-guard hook. **Do not transcribe entries into prose** — the ad stack rewrites `settings.json` sub-second, so any hand-copied table is stale on write (this is what sank the first "autonomy policy" draft). Read live, counts and hook matchers only: `jq '{allow: (.permissions.allow | length), ask: (.permissions.ask | length), deny: (.permissions.deny | length), hook_matchers: (.hooks | map_values([.[].matcher]))}' ~/.claude/settings.json`. Canonical copy + drift enforcement: `harness-doctor.sh` check 11 (permissions/hooks/env/model vs the dotfiles copy). The *convention* layer — the self-imposed pauses — lives in `CLAUDE.md` → Autonomy.

WSL user settings default to `bypassPermissions`; Auto remains disabled and bypass remains available. `sync.sh reconcile-runtime-env` owns this startup default alongside the shared runtime permission policy, migrating stale or missing live defaults while preserving unrelated permissions, hooks and env. Install invokes that reconciliation; push refuses a reverted default, and check/doctor report drift. Native Agent/Workflow/team children inherit a bypass parent. Independently launched CLI processes do not inherit a parent launch flag, so unflagged standalone launches use the settings fallback; explicit CLI permission modes still override it. Windows break-glass policy is unchanged. This configuration does not establish the mode of already-running sessions or every external launcher, nor eliminate hook/approval prompts.

- **Tiers.** `allow` runs silently, `ask` prompts, `deny` blocks. The entries live only in the file; the jq line above counts them without printing them. The hand-copied list this replaced had drifted from the live file (dotfiles#1429). Managed command-deny floor = catastrophic-only and root-owned; managed mode policy disables Auto while leaving bypassPermissions available.
- **Guard hooks (enforcement beyond `settings.json`).** `PreToolUse/git-guard.js` denies commit/push to main and history-loss git ops (each with a safer alternative and an escape hatch), `git config` writes to `core.hooksPath`/`core.fsmonitor`/`alias.*!` (exec-on-next-git-op), and commit/merge commands or `gh pr`/`gh issue`/`gh api` bodies carrying an AI attribution trailer (`ALLOW_AI_TRAILER=1`). Escapes are parsed as a leading env assignment or earlier `export`, never grepped as a substring. Identity overrides (`-c user.*`) are deliberately not a rule. Before adding or widening a git-guard rule, replay it against 60 days of real Bash commands from `~/.claude/projects/*/*.jsonl` (old guard vs new on a scratch repo) and report every decision transition. A script grep is not a usage census, and a rule that denies routine history does not ship (#862). `PreToolUse/grep-cost-guard.js` (registered right after DCG for config hygiene; hooks run in parallel) denies grep-family regexes with paired repeated single-character spans (conservative repeat product >= 900), pattern files unless fixed-string-only, and expensive literal pairs; the denial points to `rg -F`, bounded extraction, or `ast-grep`. An opaque `$var`/backtick regex runs behind an inline `ulimit -t 600; ulimit -v 8388608` prefix (#1738); `GREP_COST_GUARD_VMEM_KB` / `GREP_COST_GUARD_TIMEOUT_S` as a leading assignment change a bound (0 lifts it). Wrappers and shell command strings are not bypasses. `PreToolUse/heavy-job-admission.js` is admission, not a queue: heavy jobs must stay foregrounded and Turbo is forced to concurrency one. Exit 75 means the original command never started; retry only after transient pressure or the global lock clears, while malformed metric/configuration failures must be repaired first. `PreToolUse/settings-guard.js` — (added 2026-07-04, G2) `ask` on any Edit/Write to `settings.json`/`managed-settings.json` so the agent can't silently rewrite its own permission surface (the ad daemon rewrites `statusLine`/`spinnerVerbs` out-of-band, not via a tool call, so it's unaffected). `PreToolUse/codex-quota-guard.js` — fail-open direct-Codex preflight that denies only explicit provider unavailability (no sentinel/cooldown). `PreToolUse/whatsapp-guard.js` — re-attests the direct live link, exact versioned target/hash, executable bit, and first PATH match before auto-allowing canonical-store, read-only JSON point reads, context windows capped at 50 per side, or list/search reads with a concrete 1–200 limit; it denies shell-expanded values in recognized literal-`wacli` forms whose resolved values a permission dialog cannot show and `ask`s on literal writes. This is an accident boundary in bypass mode; renamed executable copies/links, shell aliases/functions, positional/array argv0 synthesis, indirect shell-state mutation, dynamic loaders, code-runtime laundering, and same-user check/exec replacement races remain accepted-open trades. `SessionStart/plugin-auto-update.js` — auto-updates plugins each session (**note:** this is why enabling plugins is NOT human-gated — it's automated).

- **A persona's no-write instruction, a read-only prompt, or a delegated CLI's sandbox default is not a security boundary.** PreToolUse guards fire only on this Claude Code process's tool loop and do not reach a codex exec child; treat a delegated run as ungated unless that child's own hooks or sandbox are configured (pstack vet 2026-09-18, architectural issue 3; dotfiles#1202).

Hook registrations are cached when a Claude session starts. Sync/install changes do not retrofit already-active sessions; restart them before treating a newly installed guard as active.
- **Guard hooks can silently stop firing in a long session (upstream Claude Code bug).** Hooks are cached at session start and the file-watcher misses `settings.json` replaced by atomic rename, so a guard that blocked earlier can stop blocking later in the same session (anthropics/claude-code#16047, #51420; no `/reload-settings`). `claude-loop.sh`'s default 3 h wall-clock cap outlasts the ~2.5 h hook death, so a loop run's last half hour is exposed too. Restart a marathon interactive session to re-arm main-push protection; do not rely on git-guard alone in a multi-hour session. A hook killed on the inherited 600s timeout makes the CLI ALLOW the gated tool (#84302), which `DCG_FAIL_CLOSED=1` cannot prevent. **Detector:** `hooks/lib/seam-heartbeat.js` beats from inside every first-party PreToolUse guard; `scripts/hook-seam-check.py` compares those beats with tool_use records in the session transcript (written regardless of hook health) and reports `healthy` / `stale` / `unknown` (unknown is never a failure: a session started before the heartbeat shipped cannot beat). `harness-weekly.sh` runs it report-only over a 7-day window; run it ad hoc when you suspect a guard went quiet. It complements `dcg-contract`, which proves decision logic by invoking a guard directly but cannot see whether Claude Code still invokes the hook. Concurrent sessions in the same project refresh each other's beat, so `stale` is strong evidence but `healthy` is not a guarantee.
- **Guardrail, not a jail — the laundering boundary leaks, deliberately** (convenience-over-hardening, same philosophy as the managed-floor caveat above). `deny` blocks the *friendly* command, not the *capability*: `gh api -X DELETE …` reaches the denied `gh repo/secret delete` endpoints; code runtimes (`node -e`, `python3 -c`, `curl|bash`, `uv run`) defeat the `wget`/`nc`/`eval` cluster; `git remote set-url` + `git push` = silent exfil. **Closed 2026-07-04:** the `git config` exec vector (G1) and settings-surface self-edit (G2, now `ask`-gated; doctor 11 still detects post-hoc drift). **Accepted-open trades:** `gh api` deny-bypass, remote-repoint exfil, code-runtime laundering, ungated `crontab`/`systemctl`/prod-DB — full-trust-minus-laundering; revisit only if the trust posture changes.

The fleet (`pr-handoff.sh`, `pr-owner.sh`, dispatcher) is gone (dotfiles#1872); `pro-gate-loop.sh` stays as the session-mode review driver and `lib/pr-owner-state.sh` stays because `wt-sweep.sh` and `pro-gate-loop.sh` source it. `/review-adversarial-first`, `/ce-code-review` and `/codex:adversarial-review` are operator-invoked only. ## PR ownership

Retired 2026-10-17 (merge-and-end; fleet removed by dotfiles#1872). Only `lib/pr-owner-state.sh` remains, sourced by `wt-sweep.sh` and `pro-gate-loop.sh`.

The author's plugin marketplace has one carve-out: a bot repin PR there skips review and merges on its required checks (operator ruling 2026-10-15), and since the marketplace's reconciler requests auto-merge itself on a bot PR whose diff is exactly the card it computed, nothing on this host runs for the normal case. For a repin PR left open, the author dispatches the marketplace's `repin-reconcile.yml` or runs `~/.claude/scripts/marketplace-repin-merge.sh <pr>`. That script is specific to the author's marketplace and bot (both are hardcoded at its top): it merges only a PR by that bot that changes nothing but `source.sha` and `metadata.{version,releaseId,releaseTag}` of existing plugin entries with every required check green at the exact head, then confirms main's card, and refuses if main's ruleset stops requiring the 'Pinned sources' check. Exit 3 means merge requested but unconfirmed: check the PR and main's card before re-running. Copy changes and person-opened repins take the ordinary merge-and-end path.

Ordinary `claude-loop.sh` roots targeting the local better-ccflare endpoint on port 8788 select `claude-bccf-quality-auto` rather than inheriting the operator's picker model. `lib/headless-gateway-model.sh` leaves explicit process and scoped settings model/role pins, account-selection headers, alternate provider selectors and other destinations unchanged, and opts out on ambiguous scoped settings. Claude Code stays the client; the gateway owns quota admission and provider fallback, and standard/lightweight descendants use the flagship ladder only when the gateway policy enables `workerFlagshipFallback`. No eligible capacity is a non-success.

Fix sessions retain `CLAUDE_LOOP_GUARD=1`; its authority fence is a command-text guardrail with the usual interpreter-laundering limit and adds no credential broker. A dispatcher intake draft PR (`loop-run`) is agent work, not an operator queue (ruling 2026-10-06, #1652); the dispatcher retired 2026-10-17 so no new ones open, and a session that finds one triages it and closes it or finishes it under merge-and-end. A named product choice (`pro-gate-loop.sh` exit 3) stays the operator's to make.

- Weekly report: on demand only (timer retired 2026-10-17). `~/.claude/scripts/harness-weekly.sh` runs harness-doctor, wt-sweep, branch-triage and docker-hygiene as DRY_RUN, the dcg contract and update check, launchpad freshen and memory triage. It toasts on warnings or a nonzero `flagged:N`. Log: `~/.claude/logs/harness-weekly-latest.log`.
- Failure alerting (#476): `scripts/discord-notify.sh` is the one off-machine alert primitive (Discord #agent-ops; exit 0 sent, 1 send failed, 2 usage, 3 no webhook). `systemd/harness-unit-failure-alert@.service` + `scripts/unit-failure-alert.sh` are a generic handler: add `OnFailure=harness-unit-failure-alert@%n.service` to a unit and its next failure attempts a page (Result=, ExecMainStatus=, journal tail, status probe). The doubled `.service` in the instance name is correct (`%n` is the full unit name). Ten units and the jsm-auto-update drop-in wire it (`systemd/README.md` lists them); a drop-in can set `UNIT_ALERT_JOURNAL_LINES=0` for a unit whose logs must not reach Discord. Before wiring another unit: 1h per-unit cooldown (`UNIT_ALERT_COOLDOWN`); never point the template at itself (page loop); wire only units that normally stay active or exit 0, or every ordinary run pages.
  - **"Its next failure pages" is the intent, not a guarantee.** The handler still has to find `discord-notify.sh` and the webhook has to accept the POST; a missing notifier or a failed send is a lost page with nothing above it to notice. Treat the alerter as a latency improvement over a backstop, never as the proof a job ran.
  - **`OnFailure=` fires on a narrower set of events than "the unit had a problem."** It does *not* fire for: a `systemctl stop`; a timer that is disabled, inactive, or has simply never elapsed; a unit that was never started because an ordered `Requires=` dependency failed first; a `systemctl reset-failed`; or — the live footgun for future adopters — a unit that later gains `Restart=` with `RestartMode=direct`. An external kill of a running `Type=oneshot` *is* covered. The weekly doctor stays the backstop for everything in that list.
  - **Coverage is not uniform across the wired units.** `harness-doctor.sh` asserts `ExecMainStatus` only for `backup-harness`. The other wired units have no independent service-exit check, so the alerter is their only failure signal. Alert scripts must resolve the notifier by absolute path, never a bare `discord-notify` PATH lookup: no such command is installed and a unit's minimal PATH turns it into a silently lost page.
- Hygiene timers (weekly, staggered Tue-Fri 01:15-02:05): wt-sweep, pkg-cache-prune, docker-hygiene and reclaim-sweep. All four are deletion-capable. The author's installed copies run with deletion on; the units shipped in this repo are plan-only for wt-sweep, docker-hygiene and reclaim-sweep (`DRY_RUN=1`, `STOP_ORPHANS=0`, `REAP_VOLUMES=0`, `RECLAIM_SWEEP_APPLY=0`; `systemd/README.md` lists the drop-ins that turn deletion on), and pkg-cache-prune keeps `DRY_RUN=0`. None is in sync.sh's auto-enable list (they are only in the `UNITS` copy list), because routine `sync.sh install` must not turn on deletion as a side effect. A fresh machine gets the units but not the schedule; enabling a pkg-cache-prune timer there starts real pruning immediately.
  - `wt-sweep.timer` (Thu 01:15) — `scripts/wt-sweep.sh`. The shipped unit is plan-only (`DRY_RUN=1`); the author's copy runs `DRY_RUN=0`. Same script the on-demand harness-weekly report runs as DRY_RUN.
  - `pkg-cache-prune.timer` (Tue 01:35): `scripts/pkg-cache-prune.sh` runs `pnpm store prune`, `npm cache verify` and `uv cache prune` (never `npm cache clean --force`). It also deletes orphaned `*.incomplete` partials under `~/.cache/huggingface` untouched for more than 1 day, by plain `find`. It never touches hub blobs or snapshots. Pruning costs only a re-download, hence weekly.
  - `docker-hygiene.timer` (daily 01:50): `scripts/docker-hygiene.sh` with DRY_RUN=0 AGGRESSIVE=1 REAP_VOLUMES=1. AGGRESSIVE removes images unreferenced by any container (a rarely used image is rebuilt or re-pulled next time). REAP_VOLUMES removes only dangling Supabase-labelled volumes older than 24h whose project no `$SITES` checkout declares (worktrees and `_archive` included).
  - `reclaim-sweep.timer` (Fri 02:05) — `scripts/reclaim-sweep.py`, `RECLAIM_SWEEP_APPLY=1` (new env var, mirrors the DRY_RUN convention; `--apply` on the CLI still always wins). Only ever acts on the script's existing 9-rule, age-gated allowlist (14-30 day floors, `MIN_DEPTH_BELOW_HOME=2`, open-file skip) — it cannot discover anything outside that table.

  - All four hygiene units wire `OnFailure=harness-unit-failure-alert@%n.service`. A crash or timeout also shows in `systemctl --user list-timers`, the journal, and harness-weekly's timer-health check (on demand).
- Docker hygiene: `scripts/docker-hygiene.sh` is the dev-container analogue of wt-sweep. `DRY_RUN=1` is the default, `DRY_RUN=0` applies, `JSON=1` is for agents, and the trailing `docker-flagged:N` drives the toast. It recycles zombie-choked stateless containers, removes exited containers and dangling images by enumerated ID, and reports idle or orphaned stacks. The only volume class it removes is under `REAP_VOLUMES=1` (see the timer above); a stopped Supabase stack's database volume looks like garbage, so there is no blanket prune. It enumerates because dcg blocks every bulk `docker * prune` but allows targeted `rm`/`rmi`/`restart`, and each removal is logged.
- Zombies are not orphans, and no script can reap them. A zombie has already exited, so `kill` on it is a no-op; only killing the parent clears it (Supabase studio/pg_meta health checks fork node under a shell, and the reparented child is never wait()ed by the container's PID 1). The only levers are recycling the container or stopping the stack. `wsl-watchdog.sh` kills orphans (live, ppid=1) and must not be extended to reap zombies.
- [Docker init adoption and lifecycle](harness/docker-lifecycle.md): workstation-only, explicit-first-adoption rollout. The doctor and the install path's Docker-policy check are read-only with respect to daemon config and never claim activation. `desired config present` does not prove daemon activation, and stored `HostConfig.Init` is not runtime proof. Further Docker daemon maintenance needs its own approval.
- [WSL memory bounds](harness/wsl-memory-bounds.md): kernel-enforced ceilings instead of another sweeper. `docker-containers.slice` (MemoryHigh=12G, MemorySwapMax=6G, no MemoryMax), in `SYSTEM_UNITS`. A bound helps only a job whose excess is page cache; ccflare stays unbounded.

- Launch pads: `~/SITES` main checkouts are dispatch surfaces for Agents View, never work surfaces. `SessionStart/launchpad-advisory.js` self-heals the launch checkout via `launchpad-freshen.sh --repo <top> --heal`. On the default branch, freshening may fast-forward while carrying unrelated local edits; incoming-path collisions or divergence block it (autostash disabled). First it runs `hooks/lib/stray-dot-git.js` (#1553): a `.git` git rejects on `/`, `/tmp`, the `/tmp/cc-daemon-<uid>` dirs, `$HOME` or its parent is renamed to `.git.stray-<stamp>-<8 hex>` (never deleted; a real repo is reported and left alone), because Claude Code treats any `.git` as a repo root and an empty `/tmp/.git` fenced all of /tmp for resumed background sessions. The `~` entry also covers every non-repo directory under `~`. `node ~/.claude/hooks/lib/workspace-trust.js --check` lists untrusted directories and `--seed` seeds them.
