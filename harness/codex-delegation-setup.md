Will drives Claude Code as his daily agent and delegates implementation and review to Codex CLI. Codex is installed natively on its own host with the Compound Engineering (CE) plugin. The top-level `model_provider = "better_ccflare"` pin routes all Codex requests through the local pool, which rotates across its ChatGPT accounts per request. Delegation channels:

1. **Plan-artifact handoff** — `/ce-plan` produces a goal-ready plan file for batch implementation. The Codex host executes it with `ce-work` (`codex exec --profile auto`).
2. **`/ce-code-review` + `/ce-doc-review`** — native CE plugin skills; no shell-companion reviewer wiring and no `codex-reviewer` or `codex-doc-reviewer` agents.
3. **`/codex-consult`** (the `/`-only skill `plugins/hov-stack/skills/codex-consult/SKILL.md`) — Ad-hoc read-only second opinion mid-conversation; `env -u OPENAI_API_KEY codex exec -s read-only`; returns Codex's answer verbatim + Claude's agree/disagree synthesis.
4. **No `codex` MCP server.** `~/.claude/settings.json` has no `mcpServers` block; the old server entry survives only in `~/.claude/backups/setup-optimize-20260616/global.settings.json`. Every channel is one-shot `codex exec`; only `/codex-consult` remains as a standalone Claude-side channel. Adding the `codex mcp-server` (`codex` + `codex-reply` tools) is the cleanest path to stateful, multi-round Codex consultation.

**Routing (full text; `CLAUDE.md` → Model Routing carries the short form):** delegate implementation batches of 5-7 or more units (breakeven measured in this doc). `/codex:rescue` handles ad-hoc tasks (background, resumable threads); the CE plan→Codex-host handoff handles planned work (a `/ce-plan` goal-ready plan, then the codex host runs ce-work at the model and effort in `~/.codex/config.toml`); raw `codex exec --profile auto` serves scripts. Codex edits, the session model reviews the diff, and every task carries an explicit testing directive. Worktree-targeted work uses `codex exec --cd <worktree>` (or `cd` in first), never `/codex:rescue`: rescue and the companion run in the ambient cwd (the launch dir, often the non-repo home) and `workspace-write` scopes writes to that cwd, so a task told to write a different worktree silently can't. The same trap catches repo work dispatched from `/mnt/c/Users/user`. Codex is the GPT-family lane for cross-model work. The gated `/pro-gate` review is the merge-path gate.

**Retired quota preflight (hov-stack#882).** `codex-quota-guard` rewrote or denied a Bash Codex call when the direct ChatGPT account was explicitly exhausted. `codex-pick` gave scripts the same fallback. The top-level provider pin (dotfiles#1002) sends requests through the local pool, which rotates across every ChatGPT account per request.

**Pool traps.** Plain model ids such as `gpt-6.2-sol` route through the pool since hov-router#324. After every ccflare restart the pool's capability profiles fail closed until ordinary traffic primes the Codex catalog (hov-router#325, open; plain-id routing right after a restart is untested). A profile `defaultEffort` overrides the CLI's own `reasoning.effort` and is then rejected as a conflict, so Codex at max or ultra fails through a profile that sets one (hov-router#326, open; the pool profiles set none). Codex cannot decode the pool's `/v1/models` list and falls back to `~/.codex/models_cache.json` (hov-router#1028).

**Provenance boundary.** Claude Code traffic through ccflare can be served by Anthropic or Codex accounts regardless of the requested Claude label. The statusline's `via <upstream-model>` badge names what served it. Verify the served model family before claiming an independent adversarial pass. `/pro-gate` is the browser-Pro terminal lane and uses a separate pool.

**Auth posture:** The ccflare Codex pool uses ChatGPT subscriptions. An ambient `OPENAI_API_KEY` (injected by the shell that launches `claude`, not in any static config) only feeds a reachability probe — benign — but is stripped from the codex paths above. To fully silence the `codex doctor` mixed-auth warning, `unset OPENAI_API_KEY` in the claude launcher.

**2026-08-17 — LOGIN ON WSL IS BROKEN BY DEFAULT, and the large context window is auth-gated:**
- **`codex login` (browser flow) cannot complete on this box.** Windows→WSL port forwarding is
  dead — a listener on any WSL port answers `HTTP 200` from inside WSL but Windows returns
  `WSL ERROR: UtilAcceptVsock:273: accept4 failed 110` (ETIMEDOUT). So the OAuth redirect to
  `http://localhost:1455/auth/callback?code=…` never reaches the login server, codex waits
  forever, and the session looks like it was cancelled. `codex-login.log` is the tell: it records
  "oauth token exchange succeeded" for every *successful* login, so an attempt with **no new log
  line** never received a callback at all. `--device-auth` does NOT fix this (it survives fine,
  including with stdin at /dev/null — verified; it is not an EOF problem).
- **Workaround (verified end-to-end):** leave `codex login` running, open its auth URL in the
  Windows browser, let the redirect fail, copy the whole `localhost:1455/auth/callback?...` URL
  out of the address bar, and `curl "<that URL>"` **from inside WSL**. Returns `HTTP 302`, writes
  `auth.json`, and `codex login status` flips to "Logged in using ChatGPT". The `state` is bound
  to the running login process, so the URL is single-use and dies with that process.
  Permanent fix is `wsl --shutdown` from Windows.
- **The GPT-5.6 large window is only visible to an AUTHENTICATED catalog fetch.** Logged out, both
  bundled and cached catalogs report `272000/272000` for `gpt-5.6-*`, and since
  `with_config_overrides()` computes `context_window.min(max_context_window)`, *any*
  `model_context_window` override silently collapses back to 272000 and looks inert — this is why
  the widely-circulated `model_context_window = 1000000` advice appears to do nothing. Logged in,
  the server advertises `max_context_window = 872000` and a plain override works natively.
  (1000000 is above the real cap regardless: measured 799,652 accepted / ~999,544 rejected.)
- **`codex debug models` renders the RAW catalog, not the effective window** — it does not reflect
  `model_context_window` at all. Ground truth is
  `grep -ao '"model_context_window":[0-9]*'` on the newest `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`.
  Live values: `828400` effective (95% of 872000), auto-compact at 500000.
- **`~/.codex/config.toml` remains OUT of dotfiles by design** (`$DOTFILES_REPO/codex/README.md`, `$DOTFILES_REPO/codex/sync.sh`);
  dotfiles owns only `hooks.json`. Config changes survive only as local `config.toml.bak.*`.
