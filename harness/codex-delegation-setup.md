**Routing (full text; `CLAUDE.md` → Model Routing carries the short form):** delegate implementation batches of 5-7 or more units (breakeven measured in this doc). `/codex:rescue` handles ad-hoc tasks (background, resumable threads); the CE plan→Codex-host handoff handles planned work (a `/ce-plan` goal-ready plan, then the codex host runs ce-work at the model and effort in `~/.codex/config.toml`); raw `codex exec --profile auto` serves scripts. Codex edits, the session model reviews the diff, and every task carries an explicit testing directive. Worktree-targeted work uses `codex exec --cd <worktree>` (or `cd` in first), never `/codex:rescue`: rescue and the companion run in the ambient cwd (the launch dir, often the non-repo home) and `workspace-write` scopes writes to that cwd, so a task told to write a different worktree silently can't. The same trap catches repo work dispatched from `/mnt/c/Users/user`. Direct Codex is the independent GPT-family lane (its quota preflight rewrites or denies with a receipt); nothing on the merge path needs a cross-model pass beyond the gated `/pro-gate` review.

**Quota preflight (2026-08-26, replaces the doghouse):** `~/.claude/hooks/PreToolUse/codex-quota-guard.js` checks the active direct account's `chatgpt.com/backend-api/wham/usage` response immediately before a Codex-spending Bash command. It acts only on explicit provider state (`rate_limit.allowed == false` or `limit_reached == true`). Missing/expired auth, timeout/network/non-200, unfamiliar payloads, and percentage-only saturation all fail open. There is no PostToolUse trip hook, sentinel, inferred cooldown, or stored reset. This replaced the two-sided doghouse after its hardcoded primary=5h/secondary=7d assumption read a lone 604800-second weekly primary as the 5h window and pinned healthy Codex unavailable for 90-124 hours. The incident fixture (`allowed:true`, weekly `used_percent:100`, `secondary_window:null`) is now a planted negative in the hook suite.

**Rewrite instead of deny (2026-09-04, dotfiles#991):** on explicit exhaustion the guard no longer denies first. `~/.claude/hooks/lib/codex-model-resolver.js` picks the best model that is *actually available* and the guard rewrites the command through `hookSpecificOutput.updatedInput` (`-m <slug>`, plus `-c model_reasoning_effort=<level>` only when the request's effort had to be clamped), with the receipt in `permissionDecisionReason`. Two live sources, no model names in code: the catalog (`GET chatgpt.com/backend-api/codex/models?client_version=…`; "best" = lowest `priority` among `visibility: "list"` entries, following `upgrade.model` when the replacement is itself available; Codex's own `~/.codex/models_cache.json` is reused while under 6 h old and never written) and the usage endpoint ("available" = the account `rate_limit`, except separately metered models, which carry their own `rate_limit` in `additional_rate_limits[]` joined on `limit_name == display_name`; today that is `GPT-5.3-Codex-Spark`, at 0% on its own 5h+7d windows while the account's weekly window sat at 100%). Rungs: the requested model if its meter is open → best open model on the active account → best open model on another **caam isolated profile** (`~/.local/share/caam/profiles/codex/<name>/codex_home/auth.json`, verified per command through its own usage endpoint and run as `caam exec codex <name> --no-lock -- exec …`; the `caam backup` vault is *not* a rung — it feeds `caam activate`, a machine-wide swap the resolver never performs) → **only with the explicit opt-in `CODEX_PICK_API_LANE=1`** (off by default; the standing posture since 2026-09-05 is OAuth subscription limits and no API spend, and an `OPENAI_API_KEY` is ambient in Claude Code's environment on this box, so presence alone never selects it) the best `supported_in_api` model with `-c preferred_auth_method=apikey` → deny as before, naming the banked reset when `rate_limit_reset_credits.available_count > 0`. The healthy path is byte-identical to before (no catalog fetch). A command already carrying `-m` for a model whose own meter is open passes untouched. Shapes the guard cannot rewrite safely (`node codex-companion.mjs …`, an expansion inside `-m "$MODEL"`, a `bash -c` payload it cannot re-quote losslessly) still deny, and the denial names the open lane so the model can re-issue a direct `codex exec … -m <slug>`. Rung 2 ships against the documented caam layout and fixtures; its first live use is #993's enrolment of a second profile — that run must confirm `--profile auto` layering survives the isolated `CODEX_HOME` (the probe on 2026-09-04 showed a missing `auto.config.toml` does not abort, but the `auto` sandbox/approval posture is then absent). Rung 3 is fixture-verified only and stays dormant: #993's decision is no API lane; the flag exists so the choice is reversible without a code change.

**ccflare pool rung (2026-09-05, dotfiles#1002):** better-ccflare (`127.0.0.1:8788`, the same router Claude Code uses) owns all three ChatGPT Pro OAuth accounts as `provider=codex` and exposes them to Codex-shaped clients only through **route profiles** (`GET /v1/models`; a raw `gpt-*` id on `/v1/responses` is refused — better-ccflare#324). Our pool profiles are named `codex-pool-<tier>` where `<tier>` is the last token of the physical model's catalog slug (`gpt-6-astra` → `codex-pool-astra`), so the resolver ranks pools against the live catalog rather than by name. When the local account's window is out, the rung comes right after "requested model still open": if ccflare reports at least one open `provider=codex` account (`GET /api/accounts`, keyed by the host's `ANTHROPIC_CUSTOM_HEADERS` from live Claude Code settings) and the best pool's physical model outranks what the local account can still offer (Spark), the guard rewrites to `-m claude-bccf-route-codex-pool-<tier> -c model_provider=better_ccflare` with the request's effort clamped to that model. ccflare rotates across the pool and fails closed. A run already carrying `-c model_provider=…`, or a top-level `model_provider = "…"` in `~/.codex/config.toml`, makes the guard step aside entirely: the local login is then not the account that serves it. `model_provider` is deliberately NOT flipped globally yet — the CE cross-model scripts send raw `gpt-*` ids and would break until #324 lands. Operational traps: after every ccflare restart the codex pools fail closed until a request reaches each Pro account (better-ccflare#325; prime with one tiny force-routed `/v1/messages`), the three accounts carry account-level `modelMappings` that beat provider defaults (kept at the catalog tiering: opus/fable → astra, sonnet → sol, haiku → terra), and a profile `defaultEffort` conflicts with the CLI's own effort (better-ccflare#326; the pools carry none).

**`codex-pick` (same resolver, for paths that never pass through Claude Code's hooks — scripts, cron, the Codex host):** `codex-pick --json [-- codex exec …]` prints the receipt (`account`, `model`, `effort`, `priority`, `reason`, `changed`, `catalog_fetched_at`, `banked_resets`, `rewrite`, `argv`, `accounts_skipped`); `codex-pick --exec -- codex exec …` rewrites per the receipt and runs it, propagating the child's exit code, and exits 3 without running when every verified rung is exhausted. Uncertainty fails open (runs unchanged). On PATH via `lib/manifest.sh` → `~/.local/bin/codex-pick`; `tool-smoke.sh` probes `--version`/`--help` only. The CE cross-model scripts (`cross-model-doc-review.sh`, `cross-model-adversarial-review.sh`) invoke `codex exec` from inside a bash script, so the guard never sees them; they pin their own model and are not routed through `codex-pick` today.

**Provenance boundary:** direct Codex intentionally bypasses better-ccflare. Claude Code traffic through ccflare can be served by Anthropic or Codex accounts regardless of the requested Claude label; the statusline's `via <upstream-model>` badge names what actually served it. An ambient `OPENAI_API_KEY` (injected by the shell that launches `claude`, not in any static config) only feeds a reachability probe — benign — but is stripped from the codex paths above. **2026-08-17 — LOGIN ON WSL IS BROKEN BY DEFAULT, and the large context window is auth-gated:**
- **`codex login` (browser flow) cannot complete on this box.** Windows→WSL port forwarding is
  dead — a listener on any WSL port answers `HTTP 200` from inside WSL but Windows returns
  `WSL ERROR: UtilAcceptVsock:273: accept4 failed 110` (ETIMEDOUT). So the OAuth redirect to
  `http://localhost:1455/auth/callback?code=…` never reaches the login server, codex waits
  forever, and the session looks like it was cancelled. `codex-login.log` is the tell: it records
  "oauth token exchange succeeded" for every *successful* login, so an attempt with **no new log
  line** never received a callback at all. `--device-auth` does NOT fix this (it survives fine,
  including with stdin at /dev/null — verified; it is not an EOF problem).
- **Workaround (verified end-to-end):** leave `codex login` running, open its auth URL in the
  Windows browser, let the redirect fail, copy the whole `localhost:1455/auth/callback?...` URL
  out of the address bar, and `curl "<that URL>"` **from inside WSL**. Returns `HTTP 302`, writes
  `auth.json`, and `codex login status` flips to "Logged in using ChatGPT". The `state` is bound
  to the running login process, so the URL is single-use and dies with that process.
  Permanent fix is `wsl --shutdown` from Windows.
- **The GPT-5.6 large window is only visible to an AUTHENTICATED catalog fetch.** Logged out, both
  bundled and cached catalogs report `272000/272000` for `gpt-5.6-*`, and since
  `with_config_overrides()` computes `context_window.min(max_context_window)`, *any*
  `model_context_window` override silently collapses back to 272000 and looks inert — this is why
  the widely-circulated `model_context_window = 1000000` advice appears to do nothing. Logged in,
  the server advertises `max_context_window = 872000` and a plain override works natively.
  (1000000 is above the real cap regardless: measured 799,652 accepted / ~999,544 rejected.)
- **`codex debug models` renders the RAW catalog, not the effective window** — it does not reflect
  `model_context_window` at all. Ground truth is
  `grep -ao '"model_context_window":[0-9]*'` on the newest `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`.
  Live values: `828400` effective (95% of 872000), auto-compact at 500000.
- **`~/.codex/config.toml` remains OUT of dotfiles by design** (`harnesses/codex/README.md`, `harnesses/codex/sync.sh`);
  dotfiles owns only `hooks.json`. Config changes survive only as local `config.toml.bak.*`.
