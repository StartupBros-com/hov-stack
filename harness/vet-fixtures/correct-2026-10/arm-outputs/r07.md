I found four mistakes that kept coming back, and I changed the repo so `make check` now catches three of them. It passes with the change. I also dropped a temporary file with a violation of each of the three new checks into `src/`, and each one was flagged. I removed it before committing.

**What kept going wrong**

The history shows the same pattern: an agent (claude or cursor-agent) makes a change, then Maya Okafor commits a correction. Each correction added a line to `AGENTS.md`, but the same errors came back.

1. **Status lists drifting.** The status list was copied into `models.py`, `api.py` and `export.py`. Each new status (overdue, void, disputed) was added to one or two copies and missed in the rest. That caused a 400 on `overdue`, `void` dropped from the summary, and `set_status` raising a `ValueError`. The latest correction says "third time this month".
2. **Bypassing the repo.** Agents reached into `storage._db` instead of `storage.repo`. This happened in the api lookup and again in the customer report, and the only guard was a code comment.
3. **Float arithmetic on money.** It was fixed twice, in pricing and in export formatting.
4. **`print()` in `src/`.** This was already enforced by `scripts/check.py`, and the history shows no repeats.

The rules for the first three were only written down in `AGENTS.md`. The one rule with a real check, `print()`, did not recur.

**What I changed**

I committed one change:

- **Single status list:** `INVOICE_STATUSES` is now defined only in `models.py`. `api.py` and `export.py` import it, so adding a status is a one-line change.
- **New checks in `scripts/check.py`:** these run in `make check` and in CI.
  - A status-list check fails if any module other than `models.py` redefines a status tuple.
  - A storage check fails if anything outside `storage/` imports `_db`.
  - A money check fails on float literals, `float()` and `/` in `src/`.
- **`AGENTS.md`:** I replaced the "add a status to every list" rule with the single-source rule and noted what the checks enforce.

The money check is deliberately strict: it flags any `/` in `src/`, not only division on amounts. If you add legitimate non-money division later, you'll need to adjust that check.

I did not touch the fourth item, `print()`, since its check was already in place.
