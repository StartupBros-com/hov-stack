**What kept going wrong**

Maya Okafor's commits are all corrections to agent commits. Each one fixed a rule that was already written in `AGENTS.md`, and the same three mistakes came back:
- **Status lists drifting:** `void`, `overdue` and `disputed` were each added to some of the three copies of the status list (`models`, `api`, `export`) and missed in the others. Maya's own commit message says "third time this month".
- **Bypassing `repo`:** agents reached into `storage._db` directly. This happened in the API customer lookup and again in the export customer report.
- **Float money:** float arithmetic caused off-by-a-cent errors in pricing and in export formatting.

The one rule that stopped recurring was "no `print()` in `src/`". It stopped because `scripts/check.py` fails the build on it. The other rules were only prose.

**What I changed**
- **Status list:** `INVOICE_STATUSES` is now defined once, in `models.py`. `api.py` and `export.py` import it instead of keeping their own copies with "keep in sync" comments. A new status now goes in one place.
- **New static checks in `scripts/check.py`, run by `make check` and CI:**
  - Anything outside `storage/` that imports `_db` fails.
  - In `pricing.py` and `export.py`, float literals, `float`, `Decimal` and `/` division fail.
  - Redefining a `*STATUSES` list outside `models.py` fails.
- **`AGENTS.md`:** the status rule now describes the single source. I also added a line saying to fix the code when a check fails, not weaken the check.

**Limits**
- The float check only looks at `pricing.py` and `export.py`. A new money module would need adding to `MONEY_MODULES`.
- The checks are AST-based, so they won't catch a creative workaround like a dynamic import.
