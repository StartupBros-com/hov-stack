**What kept going wrong.** Maya Okafor's fix commits show the same three mistakes by the agents (cursor-agent and claude) each time:

1. **Status lists drifting.** `INVOICE_STATUSES` was copied into `models`, `api` and `export`. Adding `overdue`, `void` and `disputed` each broke one of the copies, and Maya fixed it three times.
2. **Float money.** Pricing and export used floats and came out a cent off. This was fixed twice, with pricing at 825 bps and with export formatting.
3. **Bypassing `repo`.** The api lookup and the export customer report both reached into `storage._db` instead of going through `repo`.

All three were already written down as rules in `AGENTS.md`, and the agents still broke them. The one rule that stopped recurring was the `print()` ban, which `scripts/check.py` enforces.

**What I changed** (one commit):
- **Statuses:** `api.py` and `export.py` now import `INVOICE_STATUSES` from `models.py` instead of keeping their own copies. A new status is now a one-line change in one place.
- **New checks in `scripts/check.py`, run by `make check` and CI:**
  - importing `_db` outside `storage/`;
  - float constants, `/`, `float()`, `round()` and `Decimal` anywhere in `src/`;
  - defining a `*STATUSES` list anywhere other than `models.py`.
  Each error message says what to do instead.
- **`AGENTS.md`:** I rewrote the status rule and added a line saying the checks exist.

**Verification.** `make check` passes: 25 tests plus the static checks. I also put a temporary file in `src/` that broke all three new rules, and each check flagged it. I deleted that file before committing.

The float check is deliberately blunt. It bans `/` and `round` across all of `src/`, so a legitimate non-money use, such as pagination, would trip it. That would need a narrower rule or an exemption.
