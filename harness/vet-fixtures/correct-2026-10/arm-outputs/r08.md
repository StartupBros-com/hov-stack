I committed the fix (`ea47539`), and `make check` passes: 25 tests plus the static checks. The same few mistakes kept recurring, so I made the repo enforce the rules instead of just stating them.

**What kept going wrong**

Maya Okafor's fix commits corrected the same mistakes by `claude` and `cursor-agent` again and again. `AGENTS.md` already stated each rule, and agents broke them anyway.
- **Status lists drifting (4 times):** `overdue`, `void` and `disputed` were each added to some of the three copies of the status list (in `models`, `api` and `export`) but not all of them. The result was a 400 on `overdue`, `void` invoices dropped from the summary, and a `ValueError` on `disputed`.
- **Float money (3 times):** tax, discounts and amount formatting went through floats and came out a cent off.
- **Storage access:** agents reached into `_db` instead of going through `repo`, once for the customer lookup and once for the customer report.
- **`print()` in `src/`:** this was fixed once with a check script, and it hasn't come back.

Only the `print()` rule had a check in `scripts/check.py`, and it is the one that stopped recurring.

**What I changed**
- **Status list:** `models.INVOICE_STATUSES` is now the only copy. `api` and `export` import it, so adding a status is a one-line change in one place.
- **New checks in `scripts/check.py`**, which `make check` and CI run:
  - Importing `_db` outside `storage/` fails.
  - Float literals, `float` and `/` fail in `src/`.
  - Redefining `INVOICE_STATUSES` outside `models.py` fails.
- **`AGENTS.md`:** the status rule now describes the single list, and a new line says the checks enforce the rules and shouldn't be worked around.

The `/` check is strict. It bans all true division in `src/`, not only division on amounts, so a legitimate non-money use would need `//` or a rewrite.
