I found three classes of repeat mistake and fixed each one with a check that fails the build. The unit tests and the static checks both pass under `make check`, which CI also runs. I put the work in two commits.

**What kept going wrong**

1. **Status lists drifted.** The same list of invoice statuses was copied into `models`, `api` and `export`. Each new status (overdue, void, disputed) was missed in one copy, and that cost fix commits `ba858e9`, `99aba8a` and `3d8699b`. The AGENTS.md rule "put it in every list" was already there and didn't stop it.
2. **Storage bypass.** Agents reached into `storage._db` instead of going through `repo`. This happened in `a6b9a74` (api) and again in `5b0c424` (export). The AGENTS.md rule didn't stop it either.
3. **Float money.** Tax and discount were computed with floats, which `f7b80d0` fixed, and export totals had the same problem, fixed in `12231dd`. The rule "Money is integer cents" was in AGENTS.md but nothing enforced it.

`print()` in `src/` was already enforced by `scripts/check.py`, so I left it alone.

**What I changed**

- **Statuses (architecture):** `models.INVOICE_STATUSES` is now the only list, and `api` and `export` import it. A new test runs every status through the api and the export summary. A new check, `no_status_list`, rejects any second status list and points to the import to use.
- **Storage (lint):** `storage_only_via_repo` rejects any import of `_db` outside `storage/repo.py`. The error says to add a function to `repo`.
- **Float money (lint):** `no_float_money` rejects `float()`, float literals and `/` anywhere in `src/`. The error points to the integer approach in `pricing.tax_cents`.
- **Replay tests:** `tests/test_check.py` runs the checks against the real past mistakes. These include the float tax and discount code from before `f7b80d0`, the `_db` import from before `a6b9a74`, and a copied status list.
- **Exceptions:** an exception goes on the offending line as `# check: allow <reason>; expires YYYY-MM-DD; approved by <name>`. An expired or unapproved exception is ignored, so the check still fails.
- **AGENTS.md:** the rules are now a table pairing each rule with what enforces it. Three rules are marked "none (judgment)": standard library only, test naming, and module size.

**Why not a higher level**

- **Statuses:** I did reach the top level here, by removing the copies.
- **Storage:** I couldn't hide `_db` with Python itself, because underscore imports still compile. A check was the strongest option available.
- **Float money:** types couldn't help either. Money is a plain `int`, and Python can't forbid float arithmetic on an int.

The three judgment rules stay as docs because I couldn't find a way to enforce them mechanically.
