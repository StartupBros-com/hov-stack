I found three classes of repeat mistake and fixed each one. All of it is in one commit, `23e3885`, and `make check` passes. CI runs the same command.

**1. Status lists drifting (4 commits)**
- **Evidence:** `models`, `api` and `export` each kept their own copy of the status tuple. `overdue` (20cc060, then ba858e9), `void` (b8bd404, then 99aba8a) and `disputed` (93b3f60, then 3d8699b) were each added to some copies and missed in others. The AGENTS.md rule only said to update every list.
- **Level:** architecture. `models.INVOICE_STATUSES` is now the only list, and `api` and `export` import it, so adding a status is a one-line edit.
- **Backstops:** `no_status_copies` in `scripts/check.py` fails on any hand-written status list outside `models.py`. A new test also loops over every status through `api.set_status` and `export.status_summary`.
- **Why not a type:** statuses are plain strings, and an enum would be a larger refactor than this repo needs.

**2. Bypassing `repo` to reach `_db` (2 commits)**
- **Evidence:** a6b9a74 and 5b0c424 both had to route code through `repo` instead of `_db`. The only guard was a comment in `export.py` and a rule in AGENTS.md.
- **Level:** a check. `storage_via_repo` fails on any import of `_db` outside `storage/`, and the error tells the agent to use `repo` or add a function there.
- **Why not hide `_db`:** Python can't truly hide a module, and renaming it wouldn't stop the wrong import.

**3. Float money (3 commits)**
- **Evidence:** 225ee75 and 071766a introduced float arithmetic. f7b80d0 and 12231dd then fixed it after a one-cent error at 825 bps and rounding trouble in the export.
- **Level:** a check. `no_float_money` fails on `float()`, `round()`, `/` and float literals in `src/`, and the error points to `pricing.tax_cents` as the example to follow.
- **Why not a type:** an integer-cents type wouldn't stop `x / 100` on a plain int.

**Proof:** I replayed `src/` from before each fix. The checks fired on the pre-fix status lists, on the `_db` import in `export.py` (before 5b0c424) and on the float code in `pricing.py` and `export.py` (before f7b80d0 and 12231dd).

**Already covered:** `print()` is already enforced by an existing check.

**Rule table:** AGENTS.md now has a table pairing each rule with what enforces it. Three rules are marked as judgment calls with nothing enforcing them: standard library only, test naming, and module size. The table also says that exceptions to a check go on the offending line with a reason, an expiry date and a human's approval. The checks don't parse such markers yet, so there is no exception mechanism in practice.

I put all three fixes in one commit rather than one per class, because they share `scripts/check.py`.
