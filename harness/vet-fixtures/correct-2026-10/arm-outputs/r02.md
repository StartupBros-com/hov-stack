I found three mistakes that kept recurring, fixed each so `make check` now fails on it, and committed everything as one commit in `repo`. `make check` passes with 26 tests. CI already runs the same command.

**1. Invoice status lists drifting apart** (at least four times)
- **Evidence:** `models.py`, `api.py` and `export.py` each kept their own copy of the status tuple. Overdue (`20cc060`, `ba858e9`), void (`b8bd404`, `99aba8a`) and disputed (`93b3f60`, `3d8699b`) each needed a follow-up fix after a copy was missed. The commit message on `3d8699b` says "third time this month".
- **Level chosen:** architecture. I deleted the copies in `api.py` and `export.py`, which now import `models.INVOICE_STATUSES`.
- **Guards:** a `no_status_lists` check in `scripts/check.py` fails if anyone writes a literal list of three or more status names outside `models.py`. A new test also checks the API and the summary against every model status.
- **Why not higher:** nothing higher was available. Removing the duplication was the highest level.

**2. Bypassing `repo` to reach `storage._db`** (twice)
- **Evidence:** `a6b9a74` and `5b0c424`. The rule was already in `AGENTS.md`, and a stale "don't import _db here" comment was still sitting in `export.py`.
- **Level chosen:** a lint check, `no_storage_internals`. It fails on any import of `_db` outside `storage/` and tells the author to use `repo`.
- **Why not higher:** I didn't rename or hide the module. Python can't truly hide a private module, and the lint gives an exact error message.

**3. Float arithmetic on money** (twice)
- **Evidence:** `f7b80d0` (off by a cent at 825 bps) and `12231dd`.
- **Level chosen:** a lint check, `no_float_money`. It fails on float literals, `/`, `/=`, `float()` and `round()` anywhere in `src/`, and points at `pricing.tax_cents`.
- **Why not higher:** a `Cents` type would be stronger, but it would touch every call site. The lint is a small change that stops the pattern now.

**Proof:** I dropped a throwaway file into `src/ledgerline/` with each bad pattern (an `_db` import, a copied status tuple, a float literal and a `/`). Each one produced its named error, and I removed the file afterwards. I did not replay the original bad commits. The existing `no_print` check was already enforcing its rule.

**Rule table:** `AGENTS.md` now has a table pairing each rule with what enforces it. Three rules are marked "nothing (judgment)": standard library only, test naming, and module size. The old "new status goes in every status list" rule is gone because the mistake can no longer happen.

I didn't add any exception mechanism, since nothing needed one.
