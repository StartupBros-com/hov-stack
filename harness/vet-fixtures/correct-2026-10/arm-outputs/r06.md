Agents kept repeating the same mistakes because the repo only asked them not to. I've changed that, and `make check` passes with the new checks (commit `1824778`).

**What kept going wrong**

Maya Okafor's fix commits show three repeat offenders, each caught after the fact. Each already had a one-line rule in `AGENTS.md`, and the agents broke it anyway.
- **Status lists drifting.** The invoice status list was copy-pasted into `models`, `api` and `export`, kept in sync only by comments. A new status (overdue, void, disputed) got added to some copies and missed in others. That caused a 400 on overdue, voided invoices dropped from the summary, and `set_status` raising `ValueError` for disputed. Maya's log says it happened "third time this month".
- **Bypassing the repo.** Code reached into `storage._db` instead of `storage.repo`, once in the API and again in the export customer report.
- **Float money.** Float arithmetic on amounts caused off-by-a-cent errors in pricing and in export formatting.

The `print()` ban was the one rule that stopped recurring. It was the only one enforced by `scripts/check.py` rather than by prose.

**What I changed**

- **One status list.** `api.py` and `export.py` now import `INVOICE_STATUSES` from `models.py`. A new status is added in one place and can't be missed elsewhere.
- **Two new checks in `scripts/check.py`**, which `make check` and CI already run:
  - Any import of `_db` outside `storage/repo.py` fails the build.
  - Float literals, `float()` calls and `/` division in `src/` fail the build.
- **`AGENTS.md`** now describes the single status list and the new checks.

I ran the checks against a throwaway file with a `_db` import and a `/` division, and both flagged it. I then deleted the file. The `/` ban is blunt and applies to all of `src/`. There's currently no use of `/` there, but anyone who later needs it for a non-money calculation will have to loosen the check.
