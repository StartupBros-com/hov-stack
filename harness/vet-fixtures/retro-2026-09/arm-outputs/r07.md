I've read the session transcript and the repo's steering/config files. Here's what happened, causally: the agent hand-edited `src/db/generated-types.ts` (marked `// AUTO-GENERATED. Do not edit.`) instead of updating the real source of truth (`src/db/schema.ts`) and regenerating. That single mistake explains **both** things the user reported the next morning — the field vanishing (something later ran `pnpm db:generate` and wiped the hand-added field) and CI going red (other code now referencing a field that regeneration silently dropped). Findings below, most severe first.

## 1. No guardrail against hand-editing generated files — root cause of the incident
`src/db/generated-types.ts` is generated from `src/db/schema.ts` via `scripts/gen-types.ts` / `pnpm db:generate`, but nothing tells the agent that relationship except a one-line comment at the top of the generated file itself, which it read and overrode anyway.
- **`CLAUDE.md`** — under "Where things are," add: "`src/db/generated-types.ts` is generated from `src/db/schema.ts` via `pnpm db:generate`. Edit schema.ts and regenerate; never hand-edit generated-types.ts." (navigation pointer)
- **`.github/workflows/ci.yml`** — add a drift-check step that runs `pnpm db:generate` then `git diff --exit-code src/db/generated-types.ts`, failing CI if the committed generated file doesn't match its source. This is the fix that actually matters — it catches the mistake mechanically instead of relying on the agent reading and obeying a comment.

## 2. Lint has no teeth — two of CLAUDE.md's hardest rules are unenforced
`eslint.config.js` only applies `js.configs.recommended` (no `typescript-eslint`), and `.github/workflows/ci.yml` never runs `pnpm lint` at all. So `pnpm typecheck` happily passes on the `any`-typed `findRefund`, and nothing stops `src/core/router.ts` from importing `../internal/pg-driver.js` — a file whose own header says "Owned by src/db. Do not import from elsewhere" — which also violates the layering documented in `docs/architecture/request-flow.md` ("Handlers never touch the database driver directly").
- **`eslint.config.js`** — add `typescript-eslint` with `@typescript-eslint/no-explicit-any: "error"`, plus a `no-restricted-imports` rule blocking `**/internal/**` from anywhere outside `src/db/**`.
- **`.github/workflows/ci.yml`** — add `- run: pnpm lint` so these are enforced pre-merge, not left to the reviewer to notice (and this session's reviewer didn't).

## 3. `pnpm status-report` is a mandatory no-op that costs a full turn every session
**`CLAUDE.md`**, "Before you start": "Run `pnpm status-report` before starting any task." The script (`cat docs/status-dump.txt`) dumped 419 lines of unrelated module status for a refunds task — pure token cost, zero value observed. Remove the mandatory instruction, or scope it to tasks that actually touch deployment/module ownership. If kept, the dump itself should support filtering rather than being a flat 419-line cat.

## 4. `CLAUDE.md` names a script that doesn't exist
**`CLAUDE.md`** line 36: "Run `pnpm test:unit` before every commit." `package.json` only defines `test` (vitest), not `test:unit`. The agent hit `ERR_PNPM_NO_SCRIPT` and had to retry — a wasted tool call that will recur every session until fixed. Change the line to `pnpm test`, or add a `test:unit` alias to `package.json` if that's the intended name.

## 5. `pnpm dev` silences all output, blinding runtime verification
**`package.json`** line 5: `"dev": "tsx watch src/cli/serve.ts > /dev/null 2>&1"`. The agent explicitly started the dev server to confirm the fix worked, saw nothing after multiple retries, and gave up on runtime verification entirely — the one step that might have caught the regression before it reached CI. Drop the redirect (or tee to a log file the agent can read instead of dropping it).

## 6. `CODING_STANDARDS.md` contradicts `CLAUDE.md`
**`CODING_STANDARDS.md`** line 9: "Prefer default exports for single-export modules" directly contradicts **`CLAUDE.md`**'s "Prefer named exports over default exports." Since one file governs implementation and the other governs review, this is a standing conflict where correctly-written code can get flagged in review, or vice versa. Delete one line and pick a single convention.
