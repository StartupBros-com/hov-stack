To shrink the "Skills" line in `/context` (was ~14.2k for 157 skills), the lossless lever is **`skillOverrides`** in `~/.claude/settings.json` — NOT deletion or `jsm uninstall` (those remove capability). Verified real in the official settings schema (schemastore claude-code-settings.json). Per-skill value, enum: `on` (name+desc, default) | `name-only` | `user-invocable-only` (hidden from model, still `/`-invocable, ~0 ctx) | `off` (hidden everywhere).

**Why:** skills always load name+description at session start so the model can route — that's the whole cost. `user-invocable-only` keeps the skill installed and `/`-runnable but drops it from the model's always-on context. Nothing is lost; you just invoke deliberately.

**How to apply:** flip a skill to operator-only ONLY if it fails the test — *can a subagent run this end-to-end without a live human (interview/decision) or a human pointing at a specific local file?* If it needs the human → `user-invocable-only`. If an agent could run it autonomously → leave `on`.
- Caveats: plugin skills are NOT affected by skillOverrides. Claude Code 2.1.207 also honors overrides for bundled skills: `claude-api` is `user-invocable-only` because autonomous loading injected 556k characters in 2026-07 and locally overflowed Plan/workflow subagents. Re-measured 2026-09-22 on 2.1.280: the entry file injected on invocation is 94,183 characters (a `/context` delta of 30.8k tokens; the 75 per-language reference files, 1.35MB, are materialised to disk but never injected), and retained transcripts back to 2026-04 hold zero invocations, explicit or autonomous. The override stays: no measured benefit to weigh against a 31k-token uninvited load, and explicit `/claude-api` remains available (confirmed live). Savings register on **next session start**, not mid-session. `maxSkillDescriptionChars` is NOT a real key (don't suggest it).
- Reconciled 2026-09-22 (#1329): eight overrides that had been added to the live file without reaching the tracked copy were persisted as-is, because a live override is behavior in force: `anthropic-skills:built-in-browser`, `anthropic-skills:chrome-browser`, `anthropic-skills:computer-use`, `anthropic-skills:import-memory`, `cc-hooks` (`user-invocable-only`; the first four are plugin-scoped and may be inert per the caveat above, unverified on 2.1.280), `mock-code-finder` and `og-share-images` (`name-only`). Their origin is undocumented. The live `ubs` entry was deleted (skill removed 2026-09-21, #1297) and `testing-real-service-e2e-no-mocks: name-only`, which the tracked file carried and live had lost, was restored to live. `sync.sh push` is a wholesale live-to-tracked overwrite that strips only the two secret env keys; review its diff before committing, it does not merge.
- **Name-only is not free when the description carries an exclusion or separates the skill from a neighbour** (measured 2026-09-23, #1359, skill-tuner routing-parity with ids visible, `claude-sonnet-5`, 3 trials). With its description dropped, `sign-it` took "set up GPG so my git commits show up as Verified" 3/3 (its "Not git or code signing" clause was the only guard), `papers` lost its own request to `firecrawl-research-index` 3/3, and `anthropic-skills:pdf` lost its obvious request (to `papers`, or to a bare `pdf` answer that names no listed skill) and its paraphrase to `docx` 3/3. Self-describing names with no close neighbour (`slack-admin`, `repo-junk-triage`, `curl-bash-installer`) held at parity. Before a name-only move, run a battery whose near-misses include the skill's own exclusions and its nearest neighbours' requests; trimming a description down to its trigger phrases and exclusions is the lossless alternative (five trims landed that way in #1359).
- **Ask whether the model should invoke the skill at all before tuning its routing.** A skill whose effect is the operator's own act (signing a document in their name) is `/`-only by nature, and `disable-model-invocation: true` removes its listing cost and every misroute at once. The flag gates the Skill tool, not the skill's scripts: an agent that already knows the CLI can still run it, so claim "Claude never starts it on its own", never "no agent can sign". #1359 tuned sign-it's description for routing; the operator then ruled it `/`-only because they only ever type `/sign-it` (#1367). Put the frontmatter flag on the skill rather than a `skillOverrides` entry when it ships as a plugin, since plugin skills ignore overrides.
- **Plugin skills get a whole-plugin switch per project and no per-skill one.** Claude Code's skills docs say plugin skills ignore `skillOverrides` and are managed through `/plugin`. Measured for one plugin, compound-engineering, on 2.1.280 (other plugins and releases not re-measured) with four headless sessions in scratch dirs: a project `.claude/settings.json` holding `{"enabledPlugins": {"compound-engineering@every-marketplace": false}}` removed every compound-engineering entry from that session's `skill_listing` (attachment 29,867 -> 21,865 chars), while `{"skillOverrides": {"compound-engineering:ce-bakeoff": "user-invocable-only"}}` left it byte-identical to the control. A `permissions.deny` of `Skill(compound-engineering:ce-bakeoff)` left the listing byte-identical too. Per-project off pays only where the plugin goes unused: in the prior 30 days compound-engineering ran in 11 of the 13 repos with 3+ sessions. Per-skill control for plugin skills is upstream anthropics/claude-code#14920.
- Override keys come in three shapes, all resolved by harness-doctor check 13 since #1359: a user skill dir name, `anthropic-skills:<name>` for a claude.ai-synced skill (`skills/synced/*/<name>/`), and a bundled skill name (`claude-api`, `keybindings-help`), which has no dir.
- **A skill that a tool's description loads by name can go name-only; a skill whose connector is denied goes `/`-only** (2026-10-18, Claude Code 2.1.302). The listing was 29,444 bytes, and every bare entry in it was one of the 44 `name-only` overrides, so the budget was not yet dropping descriptions. `artifact-capabilities` and `artifact-design` went name-only, because the Artifact tool's own description tells Claude to load both by name. Six refuters found no session shape where their listing text was the only trigger, and the bundled name-only `keybindings-help` loaded by name on 2.1.302. `anthropic-skills:google-workspace` went `/`-only: its body calls the Google Drive connector's tools, and `claude.ai Google Drive` is in `deniedMcpServers`. Its description also carries the exclusions (no Google named; Word, Excel, PowerPoint or PDF) that name-only drops. Re-examine it when that connector leaves `deniedMcpServers`; claude.ai web ignores these overrides and still fires it. The other bundled skills new in 2.1.302 (`plugin-authoring`, `artifact-diagramming`, `denial-triage`) stay described: their descriptions route them, and their bodies are not on disk for a routing-parity battery. The three moves took 1,874 bytes out of the listing.
- Hard exception: **`hov-brand-voice` stays `on`** — constantly accessed by agents. Stack-specific (supabase/vercel/stripe/saas-*) and agent/meta tooling (mcp-server-design, etc.) also stay `on` — subagents legitimately use them.
- **Source of truth = the live `settings.json` `skillOverrides` map** — read it, don't trust a frozen count here. 34 skills were flipped operator-only as of 2026-07-04 (up from 16 on 2026-06-28 as jsm localizes more skills). `~/.claude/jsm-prune-plan.tsv` is a point-in-time rationale log and will lag reality.
- Churn gotcha: **keep an override even while its skill is briefly absent** (jsm localize/reinstall temporarily removes the skill dir). The override is dormant while absent and re-hides the skill the moment it reinstalls; deleting it as a "dead entry" silently un-hides the skill on its return.

Separate mechanism, same visibility surface: the `paths:` frontmatter key is documented (code.claude.com/docs/en/skills) and verified live on 2026-09-18. Claude Code loads a paths-gated skill only when a file matching the glob is in context. A paths-gated skill also refuses manual `/name` invocation when no matching file is in context. None of the 158 installed skills used it as of that date. Use it for file-type conventions only after confirming that manual-invocation gotcha is acceptable for the skill.
