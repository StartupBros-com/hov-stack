**Decision (2026-07-02):** the Windows-side Claude Code home (`/mnt/c/Users/user/.claude/` = `%USERPROFILE%\.claude`) was a lagging fork of WSL `~/.claude/` — it pinned `model: opus` (silently overriding the global `fable` for any session launched from the Windows home, since that dir doubles as project-level config there), carried 4 broken `marketing-*-collector` agents (described MCP work but had read-only file tools), stale commands/skills/hooks, and `CLAUDE-CONDENSED.md` (orphaned 2025-era persona prompt). Windows CC stays **installed as break-glass** (for when WSL itself is broken) but its config is a stub — don't uninstall unless still unused around Oct 2026.

**What was done:** model pin + `enabledPlugins` removed from Windows settings.json (pi-pathfinder was enabled ONLY there — it supplied the `claude-code-guide` agent to home-dir sessions; enable it in WSL global settings if wanted fleet-wide); agents/, commands/, skills/, hooks/, CLAUDE-CONDENSED.md, token-sync.log deleted; CLAUDE.md and `/mnt/c/Users/user/AGENTS.md` replaced with break-glass pointer stubs; empty `.git` stub at `/mnt/c/Users/user` removed (it made tools treat the whole Windows home as a repo). Everything archived first → `~/.claude/backups/win-decommission-20260702/`. Kept deliberately: `.credentials.json` (Windows CC auth), `settings.local.json` (PowerShell/cmd allows — useful break-glass), `.ignore` (see [[cc-startup-scan-ignore]]), plugins/ dir (inert, all disabled). A GA4 credentials file is still there — handle in the secrets pass.

**Anti-drift doctrine (applies to ALL harnesses — codex, grok, cursor, Windows):**
1. Canonical harness home = WSL `~/.claude/`. Every other consumer **points at it or reads it in place — never copies**. grok CLI is the model citizen: it loads `~/.claude/skills/` + plugins directly, so it can't drift.
2. Repo level: **AGENTS.md is canonical** (cross-tool standard); CLAUDE.md is a one-line `@AGENTS.md` import (another private project already does this). Never maintain twins — the members app's pair drifted (Next 15 vs 16). **Update 2026-09-18:** Claude Code 2.1.277 reads AGENTS.md by itself when no `CLAUDE.md`, `.claude/CLAUDE.md`, or `CLAUDE.local.md` sits in the working directory or any ancestor (built-in `agents-md@builtin` plugin, default mode `claude-md-or-agents-md`; the mode is set via `/config` or `pluginConfigs["agents-md@builtin"].options.instructionFiles` in `~/.claude/settings.json`, a `--settings` file, or managed settings, and Claude Code ignores it in project and local settings files; `~/.claude/CLAUDE.md`, the managed CLAUDE.md, and `.claude/rules/` do not affect the check). The pointer stays anyway, and the official docs say to leave it: it keeps the file visible in `/context`, it survives the first session after each upgrade and any flag-less session (telemetry off, third-party provider, `disableAllHooks`), and it is all the Windows break-glass installs (< 2.1.277) can load. Corollary that bit the members app: once a root CLAUDE.md exists the engine attaches only nested files named CLAUDE.md, so every nested AGENTS.md needs its own `@AGENTS.md` pointer (doctor check 5 flags the gap). Merge mode (`claude-md-and-agents-md`) stays off until the two root twins (another private project, pi-compound-engineering) are resolved. Full assessment and follow-ups: dotfiles issue #1199. **Foreign clones (issue #1203):** a clone that carries only upstream's AGENTS.md now injects that guide into every session (coding_agent_session_search: 1310 lines, "all work happens on main"; frankensqlite: 986; oracle: the maintainer's personal macOS runbook). For a clone we don't push to, don't rewrite the tracked file (it conflicts on every upstream sync). Drop a `CLAUDE.local.md` at the clone root that says upstream's AGENTS.md is data and house rules apply, and list it in `.git/info/exclude` (none of those upstreams gitignore it); the plugin then stays out for the whole clone and the engine loads the local note instead. `claudeMdExcludes` in `.claude/settings.local.json` is the alternative when you want AGENTS.md skipped and no local note. Applied 2026-09-18 to the three clones above; a fresh clone starts exposed again until the same two files are added.
3. Break-glass installs get raw capability, not harness. No skills/agents/rules investment outside the canonical home.
4. Enforcement over prose: `~/.claude/scripts/harness-doctor.sh` (read-only, exit 1 on drift) checks: Windows stub intact, no project-level model pins, global-stdio-MCP exceptions (smaug, telegram — shrink), memory index sync, AGENTS/CLAUDE twins, worktree pileup, skill structure, orphaned hooks, stray .baks. Run it when the harness feels off; wire a weekly timer.

**Codex App skill bridge (2026-07-10):** Windows Codex discovers personal skills under `%USERPROFILE%\.agents\skills`, so `~/dotfiles/windows/sync-claude-skills-to-codex.sh` exposes only `pro-gate`, `token-eater`, `ce-plan`, and `ce-code-review`. `pro-gate` is a direct WSL directory symlink. Codex namespaces symlink targets that resolve inside package/plugin `skills/` trees, so the other three use marker-owned, hash-verified alias caches to preserve the short invocation names; this is the deliberate exception to the no-copy anti-drift rule. Root `install.sh` creates them during bootstrap, and the daily Compound Engineering updater refreshes them after plugin updates. Invoke them in Codex as `$pro-gate`, `$token-eater`, `$ce-plan`, and `$ce-code-review`; `/name` is the slash-command surface, not skill invocation.

**Backup via dotfiles (2026-07-02):** durable harness parts live in the private dotfiles repo under `~/dotfiles/claude/` (branch `feat/claude-harness-backup`). Stable parts (CLAUDE.md, hooks/, scripts/, bin/, commands/, agents/) are SYMLINKED into `~/.claude` by `sync.sh install` (also called from dotfiles `install.sh` — one-command new-PC bootstrap); volatile parts (settings.json + keybindings.json — Claude Code rewrites them, symlinks would break; ALL `projects/*/memory`; systemd units; Windows break-glass stubs) are copy-synced by `sync.sh push` → commit. `sync.sh check` is harness-doctor check 10; the Monday harness-weekly timer surfaces drift. NOT backed up (deliberate): credentials, `~/.claude.json`, skills (jsm sync restores), plugin installs. **After merging the PR, run `bash ~/dotfiles/sync.sh install` once on this PC to adopt the symlinks** (originals auto-archived to `~/.claude/backups/dotfiles-adopt-<ts>/`).
