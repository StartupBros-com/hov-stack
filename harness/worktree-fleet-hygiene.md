Will runs ~6 concurrent Claude Code sessions that constantly spawn git worktrees across ~/SITES repos, so worktrees accumulate fast (was 132 across 38 repos before the 2026-06-21 cleanup).

**Reusable sweep:** `~/.claude/scripts/wt-sweep.sh` (DRY_RUN=1 default; PUSH=0 default keeps branches local). Policy: clean+pushed → remove; has work & not abandoned → WIP-commit (`git add -A`) + keep branch local + remove worktree; abandoned (>14d old & >150 behind & <2 unpushed) → bundle to `~/.claude/git-archive/<repo>/<date>/` then drop; no-remote repo → bundle + leave in place. SKIPS worktrees under `/tmp`, `.claude/jobs/`, modified <120min, held by a live process, or held by a Claude Code session (`scripts/lib/wt_session_hold.py`; a `done` job holds only the worktree it is bound to, and only for a day, see the resumable hold below): a job that is not `done`, a running session whose cwd is inside, a transcript written <120min ago under the worktree's slug, or (hov-stack#394) a transcript filed under any project whose records drive the worktree, if it belongs to a job not `done` or a live session or was written <120min ago. A transcript stays under the project its session launched from, so a session that entered a worktree or works in it with `git -C` or `cd` is seen only that way. Driving means a record's `cwd` (it follows EnterWorktree) or a tool input path (`file_path`, `path`, `notebook_path`, an absolute path in a Bash command); tool results and the text a tool writes do not count, and a relative `cd` is not seen. The paths are indexed per transcript in `~/.cache/hov-stack-wt-session-hold/` (`WT_HOLD_CACHE_DIR`), reading only bytes appended since: the first call read 7.1 GB in about 40 s on 2026-11-03, later ones about 0.5 s. `wt-done.sh` refuses an outside run on a held worktree the same way, never counting its caller's own session (`CLAUDE_CODE_SESSION_ID`); wt-sweep counts its caller, so a sweep never removes the worktree its caller drives. The cost: a running session held every worktree it had driven, reads included, until it ended. On 2026-11-03 a dry-run sweep held 76 worktrees against 42 before #394; all 34 newly held were driven by 12 working jobs or live sessions, which the old check would have removed from under them.

**Idle release (hov-stack#644):** that hold had no expiry, and on 2026-11-14 shipped worktrees it kept pinned most of the root disk's last 50 GiB. Now a mention older than `IDLE_RELEASE_HOURS` (default 24; `0` turns this off) no longer holds a worktree on its own. The helper's `--idle-hours` reads each record's own `timestamp` (the file's mtime when a record has none) and still holds when any transcript written inside the window names the worktree, or when a holding session's last recorded cwd is inside it. Live-cwd and project-dir holds never go idle. A job's hold ends in one of two ways: a done job's when its Resumable hold window closes, and an unfinished job's once no running session carries its `sessionId`, `resumeSessionId` or transcript id and its state.json was last written longer ago than the same window (hov-stack#403). The sweep then removes the worktree through its clean path, deliverables rescue included, only if it is on a branch, `git status` is clean, every ignored file is a rebuildable cache (`wt_cache_only` in `scripts/lib/wt-preserve.sh`) or a rescued deliverable, and it is shipped: HEAD on `origin/<default>`, or `wt-done --reconcile-only --idle-release-hours N` proved it against a merged PR. Plan and apply decide alike. The summary line counts `released-idle:N`. A worktree under `git worktree lock` is skipped before any other check and counted as `locked:N`, so a lock is how to keep one.

**Resumable hold (hov-stack#793):** a background job whose turn has ended is `done`, its resting state while it waits for its user, and by sweep time its process and the worktree lock are gone. Until this hold, a done job held nothing and only printed `resumable:`, so the sweep removed the worktree under every job left overnight: 27 removals on one host from 2026-11-16 to 11-19, each later resumed onto Claude Code's "Your worktree … no longer exists" notice. Now a done job holds the worktree it is bound to while its last turn ended under `WT_RESUMABLE_HOURS` ago (`--resumable-hours`; default 24; `0` turns this off). Bound means `worktreePath` or `cwd` in its state.json lies inside the worktree, its transcript is filed under the worktree's project directory, or the last `worktree-state` record of its own `<session>.jsonl` names it (a later record that replaces or clears the binding wins; agent transcripts never bind). The clock is `lastTerminalAt`, falling back to the state.json mtime only when that is absent, since Claude Code rewrites the file while a job does nothing; a time more than an hour ahead is not believed. The hold never goes idle. Past the window the job only warns, as before. wt-done's caller is excluded by either of its session ids. Bindings are kept as an optional `bind` key on each index entry, without a cache version bump. A record with no timestamp (Claude Code's `api-request-blob` copy of an earlier message) takes the time of the dated record before it in its transcript, kept per entry as `ts`, so a rebuilt index dates it as the incremental one did (hov-stack#795: the transcript's mtime at scan time paused idle release for a day after every rebuild).

**Fresh-work hold (hov-stack#721):** the session check reads only what tool calls name, so a job that drives a worktree through `bash <file>` scripts or a Codex run is invisible to it, and edits below the top directory leave its mtime, the `ACTIVE_MIN` gate's only input, untouched. On 2026-11-17 the live sweep WIP-committed and removed such a worktree under a working job. Now, before the WIP-commit, stale-bundle and branch-delete paths, the sweep skips a worktree whose newest local work is under `FRESH_WORK_HOURS` (default 24; `0` turns this off; read as decimal, so `08` is 8; anything but a whole number of at most 9 digits stops the sweep with exit 2) old. Newest local work is the latest mtime among the paths `git status --porcelain --untracked-files=all` lists (a deleted path is dated by its nearest existing directory; both sides of a rename count, staged or not; a worktree gone mid-scan is kept), and HEAD's commit time when it has unshipped commits. Clean, shipped worktrees go on to the clean path and the idle release as before. Work it cannot date keeps the worktree, and a file dated in the future holds it until that date. Gitignored files are not looked at, nor edits inside a nested checkout or submodule (`git status` lists each as one directory, dated by its own mtime), and an untouched dirty worktree still goes once its work is a day old. The skip is counted in `skipped-active:N`. The guard reads no `DRY_RUN`, but a plan counts a branch wt-done reconciles as shipped while an apply re-counts it, so an apply can hold a worktree its plan listed for removal.

**Key facts learned:**
- Removing a worktree keeps a branch's commits in the repo's ref store, so "preserve" = keep branch local; pushing is optional remote backup. It does NOT keep three things (hov-stack#384, the 2026-11-03 sweep): a session idling in the worktree; gitignored files, which `git worktree remove` deletes with or without `--force` (git 2.43), `.claude/deliverables/` included; and a detached HEAD's commits, which sit on no ref. So both scripts copy ignored `.claude/deliverables/` files, and ignored `.context/` files (compound-engineering skill state, under `dot-context/`), to `<repo>/.claude/deliverables/from-worktrees/<name>/` (verified with `cmp`, never overwriting an earlier copy), and wt-sweep pins a detached HEAD at `refs/heads/recovered/wt-sweep-<date>/<name>`. A copy or pin that fails keeps the worktree. Other ignored files (builds, caches, `node_modules`) still go with it.
- Do NOT lower `cleanupPeriodDays` to force worktree auto-sweep — it ALSO controls chat-transcript retention, which `ce-sessions` depends on.
- `worktree.baseRef` is already the correct default `fresh`; the staleness cause was drift + reuse, not baseRef.
- Several ~/SITES dirs were sibling worktrees of one repo (a private repository had 6 sibling dirs; pi-mono's real git dir is at `~/.cache/checkouts/github.com/earendil-works/pi-mono`). Cleanup consolidated these.
- Bundle only when dropping — bundling preserved branches wasted 2.3GB of redundant archives.
